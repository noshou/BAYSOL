# Pipeline

The four entry points, re-bound by the package root as `BAYSOL.seed_model`, `BAYSOL.run_model`, `BAYSOL.results`, `BAYSOL.write_log` and `BAYSOL.print_summary` (and, for the models of one measured curve on one figure, `BAYSOL.compare_results`, and for a whole project folder, `BAYSOL.run_project`, below):

```julia
using BAYSOL
seed = BAYSOL.seed_model(src, energy, q, I, σ, pH, σ_pH, solutes) # rebin = 12 per Shannon channel, lMax from the structure
res  = BAYSOL.run_model(seed) # 300 warm-up + 700 draws; run_model(seed, n_samples, n_adapt) to change
BAYSOL.results(res, seed; dir = "out") # terminal plots, pgfplots .tex, and the workbook out/res.xlsx (with `run_log = true` also the run log out/out.LOG, written last)
BAYSOL.write_log(res) # the run log out/out.LOG (what `results(...; run_log = true)` does last)
BAYSOL.print_summary(res) # what a run says at the end: one parameter, check or file per row, every line under 80 columns
```

## The stages

`seed_model` (every step is a named stage of the `Runtime.StageLog`, cache hits marked):

1. resolve the structure (`MolecularStructure`), look its residue names up (`components`), run the `structure checks` (reused chain ids, duplicate atoms, dummy-like models) and choose the hydrogenation from the content (`classify`);
2. `Hydrogenator`: PROPKA unless the structure is a nucleic acid alone, then pdb2pqr (PARSE, or AMBER for a nucleic acid alone), with modified residues hydrogenated through their parent;
3. the solvent-accessible surface and the diameter `D` of the scatterer cloud (atoms **and** beads), `Utils.Shannon` binning of the curve to `rebin` bins per channel `π/D`, and `lMax = ⌈q_max D⌉`;
4. `Scattering.forward_cache` (the Gram matrix), the priors from the buffer `solutes` (`BulkElectronDensity.ρₑ`), and `Inference.seed_sampler`.

`run_model` calls `Inference.infer` (8 chains, MAP search, harvest, mode pooling, one retry when R̂ or ESS says the run is not converged), throws `NotConvergedError` (and so reports nothing) if it is still not converged after the retry, drops each chain's warm-up, picks the MAP draw (highest non-divergent `log π`) and computes the quantile intervals and bands. Its result holds everything the workbook reports; developer diagnostics live in the dev tools (`bysl fits diagnose`).

## The figures

`results(result, seed; dir, name = "res", references, style, font, preview = true, io, tex = true, compile = false, formats, run_log = false, ref_chi2)` makes the fit (data with error bars, the posterior bounds band and quantile curves, the MAP curve; log axes), the residuals and the posterior histograms (ρₑ, δρ₁, δρ₂, δρ₃, scale, background, c1, each its own figure `<name>_hist_<parameter>` with the MAP marked), plus one comparison figure per `Reference(name, q, I; q_max)` (data, the reference curve and the MAP curve: the depositor's CRYSOL, FoXS, … fit). Every figure is prepared once as plain arrays (`_curve_data`, `_residual_data`, `_histogram_data`, `_comparison_data`) and drawn three ways:

- **in the terminal** (UnicodePlots, `preview = true`), printed to `io`; it needs nothing installed. It prints the fit (the data in orange and the MAP curve, as log₁₀ q against log₁₀ I(q)) and the residuals, both titled with the MAP's reduced χ²; the residuals are clipped to the 2–98 % range (the title counts the points outside); one orange histogram per parameter has its MAP value in the title. The bounds band and the reference curves are in the `.tex` only;
- **as a pgfplots `.tex`** (PGFPlotsX, `tex = true`): a standalone LaTeX document per figure, written without LaTeX. LaTeX is run only with `compile = true` (to `formats = (:pdf,)`, or `:png`/`:svg`, which also need poppler's `pdftocairo`/`pdftoppm`); a failed run is a warning and the `.tex` stays. It takes about a second per figure, which is why it is off by default;
- **as numbers**: the workbook described below, always written (and, with `run_log = true`, the run log).

**The layout** of the output folder `dir`: the `.tex` files, and what `compile = true` or `bysl plots render` makes from them, are in `dir/plots/`; the workbook `<name>.xlsx` is in `dir`, and so is the run log `<folder name>.LOG` (below), one file for the folder with a section for each run. `name` starts every file name, so several runs can share a folder (`res_fit1`, `res_fit2`). The subfolder name is `PLOT_SUBDIR` in `Pipeline.jl` (a fixed constant, not a setting); a folder is created when something is written to it.

Colours, line widths, marker sizes, the histogram bins, one figure size (`size_cm`, 16 × 11 cm: it fits the text width of A4 and US Letter) and the terminal plots' size are the fields of `PlotStyle` (`PlotStyle(; color_map = "#0000ff", lw_map = 2)`), each defaulting to the `PLOT_*` constant in `Params.jl`; a colour is a name `Colors.parse` reads, a `"#rrggbb"` string or a `(colour, opacity)` tuple.

**The font** of the `.tex` figures is the `font` keyword of `results` (or `PlotStyle(; font = ...)`): the name of any font that LuaLaTeX can find, a `("Text font", "Math font")` pair of `fontspec` names, or `nothing` for the LaTeX default. The default is the pair TeX Gyre PagellaX and TeX Gyre Pagella Math (`PLOT_TEXT_FONT` and `PLOT_MATH_FONT`, which make the pair `PLOT_FONT`; TeX Live packages `newpx` and `tex-gyre-math`). A single name is the text font and leaves the math font at Latin Modern Math; a pair sets both. `font_available("Name")` (also `BAYSOL.font_available`) asks the TeX Live installation, through `luaotfload-tool`, whether a name works and returns `true` or `false`; from the shell, `bysl plots fonts "Name"` does the same and `bysl plots fonts --list` lists every installed family. A font is loaded with `unicode-math`, so a figure with a font compiles only with `lualatex` or `xelatex` (`results` and `bysl plots render` pick one; `pdflatex` cannot), and a font LuaLaTeX cannot find makes the LaTeX run fail with a warning that names it and keeps the `.tex`. With only `pdflatex` installed, use `font = nothing`. The terminal plots and the workbook do not depend on the font.

**The look** of the `.tex` figures: a bold axis box (`lw_axis`, `color_axis`, black by default); ticks pointing inward on all four sides, major and minor (`color_tick`, black by default; `lw_tick` and `lw_minor_tick`, `tick_length_cm`, `minor_ticks` between two major ones of a linear axis; a log axis keeps its own); the x tick labels slanted (`xtick_angle`, 45° by default) and hung on bent ticks, each tick leaving the axis straight (`tick_stub_pt`) and then bending (`tick_elbow_pt`) towards its label, which pgfplots cannot do itself, so they are drawn as TikZ (and each plot is clipped on its own, `clip mode=individual`, for them to show outside the axis); the y labels padded from the axis (`tick_label_pad_pt`) and the x labels from their tick (`xtick_label_pad_pt`); the log axes of the fit and comparison figures start and end exactly where the data do; legends in `\footnotesize`. Each histogram has a boxed legend in the top corner over its long tail with the **MAP** (the solid line, in the MAP colour) and **μ** (the dotted line: the middle of the tallest bin, the most sampled part of the posterior), each with its value to enough digits to tell a bin from its neighbour. Every one of these is a `PlotStyle` field defaulting to a `PLOT_*` constant.

**The page** of a figure keeps a border of `PlotStyle`'s `border_pt` (8 pt) round it, so the last tick label, the legend and the axis title are not cut off at the right or top edge.

The time of each figure (its data, preview, `.tex`, LaTeX run; one stage for each histogram) and of the workbook is recorded as stages of the `plot` group of the run's timing log, which is why `results` calls `write_log` last (with `run_log = true`).

## The comparison figure

`compare_results(fits, data; names, references, dir, name = "res", style, font, preview = true, io, tex = true, compile = false, formats, table_sigfigs)` puts **one figure** together for the results of several models of the same measured curve: the measured points with their error bars (`data = (q, I, σ)`, the curve as measured, not each model's own Shannon-binned one), the fitted (MAP) curve of **every model** and every `Reference` (the depositor's fit, CRYSOL, FoXS, ...), on log axes like the other I(q) figures. `fits` are the results of `run_model` (a vector, one per model; a result without a MAP curve is left out with a warning), `names` their names (`model1`, `model2`, ... by default; they label the legend and the columns and must differ). `run_project` calls it after its model loop (below); a script can call it with the results it holds.

- **Colours and markers are assigned, not chosen per curve.** The `k`-th model is drawn in the `k`-th colour of `style.colors_compare` (the setting `PLOT_COMPARE_COLOURS`, default the colour-blind-safe Okabe-Ito set of eight) in a line of `lw_compare` pt (`PLOT_LW_COMPARE`), and starts again at the first colour after the last. Every reference is a dashed line of the one reference colour (`color_reference`, `PLOT_COLOUR_REFERENCE`) carrying the `k`-th marker of `style.markers_compare` (`PLOT_COMPARE_MARKERS`: pgfplots mark names, any of `PLOT_MARKER_NAMES`, cycling too), so the references are told apart by their markers; a dense curve carries about 14 marks (`mark repeat`). The measured points keep `color_data` and the error bars their own look.
- **The band.** With one model the posterior bounds band of the single-model figure is drawn in that model's colour (`color_band`'s opacity); with several models the bands would hide each other and are left out, the MAP curves only.
- **The terminal plot** (`preview = true`, printed to `io`) shows the data, each reference as its marker and each model's MAP curve in its colour (with its reduced χ² in the legend), as log₁₀ q against log₁₀ I(q). The `.tex` (`plots/<name>_compare.tex`, compiled only with `compile = true`) has everything.
- **The workbook** `<name>_compare.xlsx` has two sheets, so the figure can be redrawn in any program. `compare`: `q (A^-1)`, `I_measured (a.u.)`, `sigma (a.u.)` of the measured curve as given, then one column `fit_<model> (a.u.)` for each model and `ref_<name> (a.u.)` for each reference, each interpolated linearly onto the measured q (empty where the curve does not reach, exact where it lies on that grid). `legend`: one row for each column of curves with its `kind` (`data`, `fit`, `reference`), `name`, `colour` (as given) and `hex`, `marker` (a reference's), `line` style, the model's MAP `chi2` and a `note` (whether the column is on the measured q or interpolated onto it). The header row of both sheets is frozen.

The settings are `PLOT_COMPARE` (the switch of `run_project`, the keyword `plot_compare`, default `true`), and the style's `PLOT_COMPARE_COLOURS` (`colors_compare`: kind `colours`, an ordered, non-empty list of colour names or `#rrggbb`), `PLOT_COMPARE_MARKERS` (`markers_compare`: kind `markers`, an ordered, non-empty list of marker names) and `PLOT_LW_COMPARE` (`lw_compare`, at least 0). `PlotStyle`'s two lists are tuples of `Symbol`s (`PlotStyle(; colors_compare = (:red, Symbol("#0072B2")))`). With the switch off, or without references, nothing else changes: the single-model figures and workbooks are what they were.

## The workbook

`<name>.xlsx` holds every number of a run, one table to a sheet. Sheet and column names are plain ASCII (`rho_e`, `delta_rho_1`, `chi2`), the first row of a sheet names its columns, and every value is a number (a statistic that could not be computed, such as the E-BFMI of a very short chain, is an empty cell, since a spreadsheet has no `NaN`) except the labels in the first column and the text of `form_factor_log`. Every column is as wide as its longest text (up to 80 characters, then wrapped) and the header row is bold. Numbers carry `TABLE_SIGFIGS` (`Params.jl`; 17 by default, every bit of a `Float64`) significant figures. The workbook opens in Excel, LibreOffice and Google Sheets and reads with `pandas.read_excel(path, sheet_name=None)`.

| Sheet | Columns | What it holds |
| --- | --- | --- |
| `run` | `section`, `name`, `value`, `unit`, `meaning` | the run's settings and statistics, one per row, grouped by `section` (`model`, `data`, `sampler`, `convergence`, `output`) and each explained (below) |
| `map` | `parameter`, `value` | the MAP draw: `log_density` (the log posterior density), `rho_e` (buffer electron density, e⁻/Å³), `delta_rho_1`, `delta_rho_2`, `delta_rho_3` (hydration-shell contrasts), `scale`, `bkgrnd_corr` (detector scale and background), `excl_vol_corr` (the profiled excluded-volume correction `c1`), `chi2` (reduced χ² **on the measured points**, `n_raw − 3` degrees of freedom: scale, background, `c1`; the grid CRYSOL and FoXS evaluate, whatever the binning) |
| `quantiles_<interval>` | `parameter`, `quantile_lo`, `quantile_hi`, `bound_lo`, `bound_hi` | the same parameters: the posterior quantile pair (default `2sigma`, the 2.28 and 97.72 percentiles; `run_model(seed; sigma = 1)` changes it, and the `run` sheet gives the percentiles as `quantile_lo_pct` and `quantile_hi_pct`) and the extreme draws that lie inside it |
| `stdev_from_prior` | `parameter`, `z_map`, `z_quantile_lo`, `z_quantile_hi` | for the four parameters with a prior (`rho_e`, `delta_rho_1..3`): how many prior standard deviations (θ-space) the MAP value and the quantile pair lie from the prior mean |
| `modes` | `mode`, `share`, `log_mass`, `log_mass_err`, `chains`, `kept` | only when the chains settled in more than one posterior mode: each mode's share of the posterior mass by bridge sampling, its log mass and error (nats), its number of chains, and whether it keeps draws (`kept` is 0 for a share below 1e-4) |
| `optima` | `optimum`, `share`, `chains`, `started` | only when more than one local optimum carries mass: its share of the Laplace mass, the chains that ended there and how many of them started there |
| `form_factor_log` | `line` | text; only when form-factor parsing logged something |
| `data` | `q`, `I`, `sigma` | the curve the fit saw (Shannon-binned) |
| `model` | `q`, `I_map`, `quantile_lo`, `quantile_hi`, `bound_lo`, `bound_hi` | the MAP curve and the posterior quantile and bounds curves |
| `residuals` | `q`, `I`, `sigma`, `I_map`, `residual` | data, MAP curve and `(I − I_map)/sigma` |
| `hist_<parameter>` | `bin_lo`, `bin_hi`, `count` | the counts of one parameter's histogram (non-divergent draws), seven sheets |
| `draws` | `chain`, `draw`, `rho_e (e-/A^3)`, `delta_rho_1..3 (0.03 e-/A^3)`, `scale`, `bkgrnd_corr (a.u.)`, `excl_vol_corr (c1)`, `chi2_fit_grid`, `log_density`, `divergent`, `tree_depth`, `n_steps`, `step_size`, `acceptance_rate` | one tidy table, a row for each posterior draw of the pooled chains (frozen header, units in the header text): `draw` counts from 1 within its chain (the NUTS iteration is `n_adapt` + `draw`); the four sampled parameters; the quantities derived from each draw that the result already holds (nothing is recomputed: `chi2_fit_grid` is the reduced χ² on the fitted, Shannon-binned grid, where `map`'s `chi2` is on the measured points); the sampler's flags of the draw (`divergent` is 1 for a divergent transition; a flag the statistics do not carry has no column). The `run` sheet's `draws_rows` row counts the rows and explains the sheet |
| `ref_<name>` | `q`, `I` | a reference curve given to `results` |

**The `run` rows**, in order (a row is absent when the run did not record it):

- Sizes: `n_atoms` (atoms of the hydrogenated structure), `lmax` (highest spherical-harmonic degree of the scattering model), `n_q_raw` (measured points), `n_q` (points fitted after binning).
- Sampler settings: `n_samples` (NUTS iterations of each chain, warm-up included), `n_adapt` (the warm-up part), `rng_seed` (0 unless changed; the same seed reproduces the run), `quantile_lo_pct` and `quantile_hi_pct` (the percentiles of the interval that `sigma` asked for). `pmv_fallback_uncert` (cm³ mol⁻¹, the uncertainty given to a non-biological buffer solute whose table row states none; the setting `PMV_FALLBACK_UNCERT`, not recommended to change).
- Shannon binning: `dmax` (Å, the maximum diameter of the atoms and hydration-shell beads), `channels` (q range × `dmax` / π, the number of independent Shannon channels), `rebin_channels` (bins per channel; 0 when the curve was fitted as measured), `rebin_measured` and `rebin_fitted` (points before and after), `rebin_non_positive_dropped` (bins with a non-positive mean that were dropped).
- Sampler statistics: `iterations` (post-warm-up transitions of the pooled chains), `mean_accept` (mean acceptance rate; the target is `TARGET_ACCEPT`), `tree_depth_avg` and `tree_depth_max`, `mean_n_steps` (leapfrog steps per iteration), `ebfmi` (energy-based fraction of missing information of the worst chain; below about 0.3 the momentum resampling explores poorly), `cavity_frac` (share of the hydration-shell volume carried by cavity beads; near 0 means `delta_rho_3` has no likelihood and its posterior is its prior), `excl_vol_sat` (0, +1 if `c1` sat on its upper bound at the MAP, −1 on its lower), `divergence_rate` (share of divergent transitions).
- Output: `quantile_lo_pct` and `quantile_hi_pct` (above) and `draws_rows` (the rows of the `draws` sheet, with the sheet's columns explained in its `meaning`).
- Chains: `chains_pooled` (chains whose draws are kept) of `chains_run`, `rhat_max` (worst rank-normalized split R̂ over the four parameters and the log density; above 1.01 the chains have not converged), `ess_min` and `ess_tail_min` (smallest bulk and tail effective sample sizes; below 400, or not computable, the run counts as not converged too), then, when they apply, `modes` and `optima` (their counts, with the sheets above), `rewhitened_nats` (log-density gain when the chains found a better basin than the MAP search) and `retry_first_rhat` with `retry_kept` (the first run's R̂ when it was rerun, and 1 if the rerun was kept).

## The run log

`write_log(result; ref_chi2)` writes the run log: the file `<folder name>.LOG` of the output folder, **one file for the folder with a section for each run** (`=== fit3 ===`, named after the workbook, the folder's own name for `res.xlsx`); a second call replaces the run's own section. `results(...; run_log = true)` calls it last (`run_log` is `false` by default; every fitting-test script sets it). It is what a benchmark needs and no more. The first line, `datetime`, stamps the last write (day, 24-hour time, offset from UTC). A section is, in this order: **the run** as flat rows `name`, spaces, a tab, `value` (the cells are padded with spaces to a multiple of 8 and followed by one tab, so the columns line up at any tab width and a line still splits on its tabs): BAYSOL `revision` (with `-dirty` when tracked files have uncommitted changes, so that a run is tied to a commit only when the tree is clean), the `julia` version, the `baysol` version with its release name (`v0.3.0-wʋsg_n_yɩɩda`: the `version` and the `release_name` keys of `Project.toml`, changed together at a release), the `ref_chi2` (the depositor's χ² with its method, if given), the kind of `structure` and the pdb2pqr cache, the conditions it was given (`temperature_c`, `ph`, `sigma_ph`, `energy_ev`), the atoms, the model and data sizes, the sampler's settings and the seed, the fit (the reduced `chi2` on the measured points, the MAP of `rho_e`, `delta_rho_1..3`, `scale`, `bkgrnd_corr` and `c1`, their `z_` scores from the prior, whether `c1` sits on a bound) and the sampler's health (`divergence_rate`, `n_divergent`, `rhat_max`, `ess_min`, `ess_tail_min`, `ebfmi`, acceptance, tree depth, leapfrog steps and ms/step, the chains, `modes`, `optima`, a retry or a re-whitening); **`--- timing ---`**, the timing table as the reports always showed it, for a person to read: the stages indented by level, with seconds, `% wall`, `(JIT)` and `(GC)` on every row and a `notes` column at the end of the row (short, on the same line, without brackets: what the stage's name carried, such as the NUTS iterations and leapfrog steps or the MAP search's starts, and its own note, such as `cache hit`), the wall clock first (it starts with the process, Linux; elsewhere with the load of BAYSOL, the `startup` being the time before `seed_model`), the `plotting` group, `report write` and `unaccounted`, then `GC:` (the process's total) and the two halves of the wall clock, `fit timing` (everything but the plotting) and `plot timing`; and last **`--- machine ---`** (`machine.os`, cpu and its clock, cores, Julia threads, memory, the load and the free memory when the run started). A number that could not be computed (an E-BFMI of 0/0) has no row. `ref_chi2` is given to `results` as `ref_chi2 = "CRYSOL 1.37"`. Residual statistics (lag-1, runs z) are in no output; `bysl fits diagnose --residuals ID` prints them. The fitting-test scripts under `test/fitting_tests/` are deliberately self-contained examples of these calls.

## The settings of the user

The terminal interface keeps the settings a user changed in `settings.json` in the BAYSOL folder (`BAYSOL.settings_file()`: `$BAYSOL_HOME`, else `baysol` in the data folder of the system). `BAYSOL.load_settings()` reads it and gives the value of every setting, the saved one or the default, in the type the default has (an `Int`, a `Float64`, a `Tuple`, and so on); a missing file gives the defaults. **Nothing illegal gets through:** every saved value is checked before it is used, against its type, the `SETTING_LIMITS` and `SETTING_CHOICES` of its `Params.jl`, a colour that exists, the shape of a tuple, and the `SETTING_RELATIONS` that tie settings together (`MODE_δρ₁₂` strictly inside `BOUNDS_δρ₁₂`, `SASA_N_OCC` at most `SHELL_SAMPLE`, an opacity between 0 and 1, ...). A file that cannot be read, or one invalid value, prints a warning for each problem and throws an `InvalidSettingsError`, so the fit that asked for the settings does not start. The terminal interface makes the same checks (on the same data, `bysl harvest defaults` writes it) each time a setting is saved, a sheet is opened or a project is opened; there an invalid value is wiped, back to its default, and the setting says so. The entry points `seed_model`, `run_model` and `results` do not read the file themselves: the caller passes what `load_settings` returns.


## The buffer of a project

`BAYSOL.load_buffer(path)` reads the `buffer.json` that the terminal interface keeps in a project (concentrations in mM as typed) and returns the `Vector{Solute}` that `seed_model` takes, in file order, with the concentrations and their uncertainties divided by 1000 (mol/L). **A missing file is an error** (`InvalidBufferError`): BAYSOL does not guess a buffer, since a run on pure water by accident is worse than a stop. A file with no solutes is accepted with a warning (`the buffer has no solutes: pure water`). The file is an object with a `solutes` array; the schema is frozen in `test/fixtures/buffer/buffer.json`, which the interface's tests and `test_loadbuffer.jl` share:

| `kind` | Keys besides `mM`, `sigma-mM` (required; `mM` above 0, `sigma-mM` at least 0) | Solute |
| --- | --- | --- |
| `"nonbiological"`, `"polymer"` | `arg` (table name; grade or family string) | `NonBiological`, `Polymer` |
| `"dna"`, `"rna"`, `"protein"` | `arg` (the clean sequence) | `DNA`, `RNA`, `Protein` |
| `"custom-nonbio"` | `custom` (name), `z`, `pmv`, `sigma-pmv` (null = the fallback) | `CustomNonBio` |
| `"custom-polymer"` | `custom` (name), `units` (1 to 4 of `z`, `slope`, `sigma`), `counts` (one per unit), `z-ends`, `pmv-ends`, `sigma-ends` (null = none) | `CustomPolymer` |

The file also holds the pH of the buffer and the standard uncertainty of it, `"pH"` and `"sigma-pH"` next to `solutes` (the terminal interface calls the second one σ). They come as both or neither: a pH from 0 to 14 and a `sigma-pH` from 0 to 14 (the limits are `BUFFER_PH_MIN` and the like, the same numbers as `tui/assets/data/buffer_conditions.json`). `load_buffer` checks them when they are there and does not need them; `BAYSOL.load_buffer_ph(path)` returns `(pH = ..., σ_pH = ...)`, the `pH` and `σ_pH` of `seed_model`, and throws an `InvalidBufferError` when the buffer has none, because a run needs a pH.

`name`, `source`, `record` and a unit's `label` and `formula` are labels only. The loader checks the shape (kind, keys, types, the concentration, the list lengths) and prints a warning for each problem before it throws one `InvalidBufferError` that lists them with 1-based row numbers; the ranges of the numbers (electrons above 0, a finite volume, a chain of at least 2 units) are refused by `ρₑ`, not repeated.

**Every setting is a keyword.** The settings of `settings.json` are not the only way to give a value: each one is a keyword of `seed_model`, `run_model`, `results` or `run_project`, named after the setting in lower case (`MAP_N_STARTS` is `map_n_starts`; the older keywords keep their names: `thickness` for `SHELL_THICKNESS`, `probe`, `sigma` for `VAL_SIGMA`, `δ` for `TARGET_ACCEPT`, `n_adapt` and `n_samples = N_ADAPT + N_DRAWS`, `tex`, `compile` and `formats` for the `FIGURES_*`), with the `Params.jl` constant as its default, so a library user passes what the interface would have saved. `seed_model` takes the geometry, hydration-shell, prior and c1 settings, the data and structure settings (below) and (`thickness`, `probe`, `κ_δρ₁₂`, `κ_δρ₃`, `pmv_fallback_uncert`, `bounds_δρ₁₂`, `mode_δρ₁₂`, `φ_max`, `excl_vol_corr_bounds`, `excl_vol_corr_eps`, `shell_area_per_point`, `shell_min_points`, `shell_sample`, `sasa_n_occ`, `bead_ray_range`, `bead_ray_dirs`), `run_model` the sampler (`sigma`, `δ`, `rng_seed`, `n_chains`, `retry_n_adapt`, `retry_n_draws`, `chain_start_radii`, `optimum_chain_cap`, `optimum_min_chains`, `optimum_chain_radius`, `optimum_chain_fraction`, `map_max_iter`, `map_n_starts`, `map_f_successive`, `map_optima_kept`, `map_jitter_radii`, `map_jitter_directions`, `map_jitter_max_optima`, `map_jitter_within_nats`, `basin_restart_nats`, `harvest_cover`, `harvest_divergent`) and `results` the table precision `table_sigfigs`, `tex`, `compile`, `formats`, `plot_tui_sizes` (with the folder `tui_dir` to write the sizes into) and the `style` (a `PlotStyle`, the plot look). The keywords that are new (everything of the sampler and the model that had none) are checked **as `load_settings` checks the setting of the same name**: the type, the limits and the rules between settings (`MODE_δρ₁₂` strictly inside `BOUNDS_δρ₁₂`, `EXCL_VOL_CORR_EPS` within the width of `EXCL_VOL_CORR_BOUNDS`, `SASA_N_OCC` at most `SHELL_SAMPLE`, positive radii), and a bad value throws the same `InvalidSettingsError`, with the line `SETTING = value: what is wrong` that the file would give (its closing sentence says that the values were keywords). The older keywords keep their own errors. The constants of `Params.jl` stay the single definition: the keyword's default is the constant, and nothing is a mutable global.

Three helpers turn the settings of `load_settings()` into the keywords, to splat: `BAYSOL.seed_keywords(settings)` for `seed_model(...; seed_keywords(settings)...)` (24 keywords), `BAYSOL.run_keywords(settings)` for `run_model(seed, args...; run_keywords(settings)...)` (22) and `BAYSOL.results_keywords(settings)` for `results(...; results_keywords(settings)...)` (`table_sigfigs`, `tex`, `compile`, `formats`, `plot_dir`, `latex_compiler` and the `style` of the `PLOT_*` settings). `n_samples` and `n_adapt` of `run_model` are positional, so `BAYSOL.run_arguments(settings)` gives `(n_samples, n_adapt)` for `run_model(seed, run_arguments(settings)...; run_keywords(settings)...)`. The table behind them is `SETTING_KEYWORDS` (setting, keyword, entry point); a test checks that every setting of the catalog is in it and that its keyword exists.

`run_project` takes all of these keywords too (each defaults to `nothing`: take the project's `settings.json`; for the settings that may be `nothing` itself, `q_min`, `q_max` and `lMax`, the default is `:settings` and a `nothing` clears a saved value); a value overrides the file, and the merged set is checked once, before any model, so a bad value or a broken rule fails the run with an `inputs` error.

### The data and the structure of a fit

Eight settings choose what is fitted, each a keyword of `seed_model` (and of `run_project`), a row of the catalog and, where it differs from its default, a row of the run's LOG and `run` sheet. **With every one at its default the seed is what it was before they existed** (a test compares the seeds and a seeded run).

| Setting | Keyword | Default | Meaning |
| --- | --- | --- | --- |
| `Q_MIN`, `Q_MAX` | `q_min`, `q_max` | none (`nothing`) | fit only the points with `q_min ≤ q ≤ q_max`, Å⁻¹; `Q_MIN` must be below `Q_MAX` |
| `SIGMA_SCALE` | `sigma_scale` | 1 | multiply the measured errors by this factor (above 0) |
| `EXCLUDE_Q` | `exclude_q` | `()` | ranges `((q_lo, q_hi), ...)` whose points are left out, `0 ≤ q_lo < q_hi` |
| `LMAX` | `lMax` | automatic (`nothing`) | pin the spherical-harmonic band limit (an integer at least 1) |
| `CHAINS` | `chains` | `()` (all) | keep only these chain ids (one character each, case counts) |
| `MODEL` | `model` | 1 | which model of a multi-model file (counted from 1 in file order) |
| `ADD_HYDROGENS` | `add_hydrogens` | `true` | add hydrogens with PROPKA and pdb2pqr |

The three data keywords act first, on the measured curve, before the structure is touched and before the Shannon binning, so the channels, the band limit and the bias bound of the binning follow the range that is fitted, and the curve the range leaves is the measured curve of the run (the chi-squared and the plots on the measured grid are over those points; `n_q_raw` counts them, and `n_q_input`, `n_q_cropped` and `n_q_excluded` say what was left out). A bad point inside an excluded range is never looked at. A range that leaves fewer than 3 points, or a curve that has fewer than 3 after the binning and the dropping of non-positive bins, is an `ArgumentError` that names `q_min`, `q_max` and `exclude_q` (the scale and the background are fitted, so 3 points are the least), where it was once a `WLSError` in the middle of the build. `q_min`, `q_max` and `lMax` take `nothing` for "no limit" and "automatic": in `settings.json` that is JSON `null`.

What the structure reader does, and what a keyword changes:

| | Today |
| --- | --- |
| Model of a multi-model file | the first whatever its number; `model` picks the k-th (a .pdb: its k-th `MODEL` block, written to its own file of the store; an mmCIF or download: the k-th BioStructures lists) |
| Chains | all; `chains` keeps some (a text filter on the .pdb before the hydrogens are added; a chain the file lacks is an error that lists the chains it has) |
| Waters, ions, ligands, saccharides, `UNK` | never part of the model (the loader keeps ATOM records and the HETATM of nucleotides and peptide-linking amino acids); not a keyword: pdb2pqr has no parameters for them and waters would count the hydration shell twice |
| Modified residues (`MSE`, `SEP`, `PSU`) | kept, hydrogenated through their standard parent or base |
| Alternate locations | the conformer BioStructures makes the default (highest occupancy, the first on a tie); not a keyword |
| Hydrogens already in the file | kept as they are when `add_hydrogens` is off; with it on, pdb2pqr places the hydrogens |
| Hydrogens | `add_hydrogens` (setting `ADD_HYDROGENS`) |
| Titration method (PROPKA or none) and force field | chosen from the residue content (PARSE, AMBER for a nucleic acid alone); a guardrail, not a setting |
| pH | the buffer's, `buffer.json` |

The functions and `InvalidBufferError` are public in `BAYSOL` (reached qualified, like the other entry points: `BAYSOL.load_buffer`, `BAYSOL.load_buffer_ph`, `BAYSOL.seed_keywords`, `BAYSOL.run_keywords`, `BAYSOL.run_arguments`, `BAYSOL.results_keywords`, `BAYSOL.InvalidBufferError`) and exported from `Pipeline`.

## The run of a project

`BAYSOL.run_project(project_dir; temperature, ui = :cli)` fits **every model of a project folder** in one process and writes the run folder `<project>/runs/<stamp>/` (`stamp` is the local time, the zone label, the offset from UTC and the date, `HH-MM-SS-mmm_TZ_±HHMM_YYYY-MM-DD`, e.g. `23-35-29-123_EST_-0500_2026-11-07`: only digits, letters, hyphens and underscores; the zone label is the platform's `Libc.strftime("%Z")` when it is 3 or more Unicode letters (accents kept, whitespace removed), else the zone's name from `TZ` or the `/etc/localtime` link (`Istanbul`, `SaoPaulo`), else `LOCAL`, never `GMT` or `UTC` as a stand-in; `run.json` times stay ISO-8601 UTC; macOS and Windows untested). It is what the terminal interface starts as a child process; it knows nothing of the interface and can be started from any shell. The project holds `settings.json` (what `load_settings` reads: the settings of this project; missing means the defaults), `buffer.json` (the solutes with `pH` and `sigma-pH`, read by `load_buffer` and `load_buffer_ph`), `data.tsv` (three tab-separated columns q, I, sigma, no header) with `data.json` (`units`, `"nm-1"` or `"A-1"`: q is divided by 10 for `"nm-1"`; `energy`, the X-ray energy in eV; other keys such as `mapping` are ignored) and `models/` (`.cif` and `.pdb`) and, optionally, `reference-fit/` (the old name `references/` is still read) and `model-settings.json` (below). The `temperature` (°C) is the buffer's; it has no uncertainty.

```
<project>/runs/<stamp>/
    run.json         status running|done|failed|aborted, pid, host, started/heartbeat/ended, versions, the models
                     (name, full path, size, sha256, status, error, plot_sizes, overrides), rng seed,
                     timings, and the `compare` entry once the comparison was made (below)
    logs/            settings.json buffer.json solutes.json data.tsv data.json models.json   (the snapshot)
                     model-settings.json   (if the project has one)
                     reference-fit/   (the reference curves, copied from the project)
                     run.LOG   (the whole output, then `--- result ---` and, if anything failed, `=== ERRORS ===`)
                     plots.txt (the unicode plots of every model, plain text)
    <model>/         one per model (its file stem; a clash gets `-2`; `logs` is taken)
        <model>.LOG  the log of the fit (`write_log`); a failed model has `status` and `error` rows
        output/      <model>.xlsx, plots.txt, plots/*.tex (and the rendered files when the settings compile);
                     with `ui = :tui` also plots_<W>x<H>.txt, one per size of `PLOT_TUI_SIZES`
    compare/         the combined comparison (when `plot_compare` is on and a model finished):
                     <run>_compare.xlsx, plots.txt (with `:tui` also plots_<W>x<H>.txt),
                     plots/<run>_compare.tex (and the rendered files)
```

- **The inputs are copied into `logs/` first and the run reads only the copies** (`solutes.json` is made from them: every solute with its electrons `Z`, partial molar volume and uncertainty at this pH, custom solutes as their snapshot, a sequence as its length and first residues, and the buffer's `rho_e`), so editing the project during the run changes nothing. A file already in `logs/` (a caller that took its own snapshot under its locks) is used as it is.
- **The folder is claimed** with a non-recursive `mkdir` (when the stamp exists, the next millisecond), after a check that no run of the project is live (`running`, a heartbeat under 60 s old, and the pid exists on this host: otherwise `a run is in progress (pid N)`). A caller that claims it itself passes `run_dir`.
- **`run.json` has one writer**, this function, which replaces it atomically (a temporary file renamed over it) at every change and every 10 s (`heartbeat`). The run folder, the keys and the states are a protocol with the interface (`RUN_*` constants in `RunProject.jl` are guardrails, not settings).
- **Failures do not stop the loop.** An exception while fitting one model (a missing form factor or radius, an unresolved residue, a run that did not converge) is caught, its message and stack go to the ERRORS section of `run.LOG`, the model is `failed` and the next one starts (the line on stderr is short, `model <name> failed: <reason>`, with `not converged` for a `NotConvergedError` and else the first sentence of the message cut to 50 characters; `run.json` and `run.LOG` keep the whole message); an invalid input (buffer, settings, data) fails the run before any model. The run ends `failed` if anything failed and `done` otherwise. Ctrl-C, SIGTERM and, with `ui = :tui`, the end of standard input (the interface died: the process exits, nothing is left over) end it as `aborted`, the files finished (the running model `aborted`, the rest `skipped`).
- **`ui = :cli`** prints the plots as well as writing them; **`:tui`** never prints them (`plots.txt` only, and the other sizes below). The log, the summary of each fit and the sampler's output always go to stdout/stderr and are copied into `run.LOG`.
- **The plot folder and the LaTeX compiler** (the settings `FIGURES_DIR` and `FIGURES_COMPILER`, the keywords `plot_dir` and `latex_compiler` of `results`, the kind `path`: text without control characters, empty for "not set", at most 4096 characters). With a `plot_dir` that is not `""`, `results` also copies its `.tex` figures into that folder (made if missing, a file of the same name replaced; the copies are not in the files returned). `run_project` gives each model the place `<plot dir>/<project>/<run>/<model>/` in it (one folder for all projects: the layout the terminal interface moves and compiles plots to; its own default, when the setting is empty, is the `plots` folder of the BAYSOL data folder, and a Julia run with the setting empty copies nothing). `latex_compiler` is the path of the compiler that `compile = true` runs (`lualatex`, `xelatex` or `pdflatex`, named by its file, `.exe` allowed): that compiler and no other is used, and a path that is not a file or not one of the three is an error (a warning of the failed figure, as any failed LaTeX run); a font needs `lualatex` or `xelatex`. `""` keeps the old rule: with a font `lualatex`, else `xelatex`, without one the first engine PGFPlotsX finds. Both are settings of the whole run, not of one model. `compare_results` does not take them.
- **The terminal plots at several sizes** (`ui = :tui`; the setting `PLOT_TUI_SIZES`, the keyword `plot_tui_sizes`, the kind `sizes`). A text plot cannot be resized afterwards, so a viewer that has to fit a window needs it drawn at several sizes beforehand. Besides `plots.txt`, which keeps the size of `PLOT_PREVIEW_SIZE` and is exactly what it always was, the run writes `plots_<W>x<H>.txt` into the same folder (each model's `output/`, and `compare/`) for every pair `(W, H)` of `PLOT_TUI_SIZES`: the same text as `plots.txt` (a title line above each boxed plot, a blank line between), `W` the width in terminal columns of the WHOLE plot (axis labels, ticks and legend included: the drawing is made at an area width that is corrected until its widest line is `W`) and `H` the rows of the plot area (the title, the borders, the ticks and the label add 5 rows to a curve plot; a histogram has about `H` bins and is cut down until it is at most `H + 5` rows). The default is `((76, 5), (100, 9), (130, 13), (170, 18))`: the smallest is 76 columns by 10 rows, which fits a window of 80 by 24. A list is valid when it is non-empty, every size is at least 24 by 3 and at most 400 by 100, and each size is larger than the one before in both width and height (the message is `PLOT_TUI_SIZES = ...: must grow in both width and height...`); in `settings.json` it is a list of `[width, height]` pairs. A plot whose labels need more room than the request (the residuals plot needs about 60 columns, a legend with long names more) is drawn as wide as it needs and cannot be cut, so the file's real size is measured: each model's entry of `run.json`, and the `compare` entry, has `plot_sizes: [{file, width, rows}]` in the order of the setting (`file` relative to the run folder, `width` the widest line in terminal cells, as a viewer counts them, a braille blank U+2800 being one cell, `rows` the lines of the tallest plot in the file), the empty list with `ui = :cli` (which prints the default size only). The drawing at all sizes costs about 5 ms for the nine plots of a model once the code is compiled (about half a second more for the first model of a process). Measured on the crambin fixture (the fit and residuals plots, and the seven histograms; `rows` of the tallest): requested 76 by 5 gives 76 columns and 10 rows, 100 by 9 gives 100 and 14, 130 by 13 gives 130 and 18, 170 by 18 gives 170 and 23.
- **Settings of single models** (`model-settings.json`, the keyword `model_settings`). A model may be fitted with settings of its own, on top of the project's: the file `<project>/model-settings.json` holds `{"<model>": {<sheet>: {"<SETTING>": {"value": ...}}}}`, the shape of `settings.json` for each model (the model is its file stem, the sheet names are free and only group the entries), read and checked as `settings.json` is (every value against its type and limits, then the rules between settings on the model's whole set). It is sparse: a model or a setting that is not in it is the project's. The keyword `model_settings` is a `Dict` or `NamedTuple` from a model name to a `Dict` or `NamedTuple` of keywords (`model_settings = (; crambin = (; q_max = 0.3, n_chains = 8))`) and wins over the file; `nothing` clears a setting that may be `nothing` (`q_max`). The order of strength is `model_settings`, the file, the keywords of the call (`q_max = 0.3` for every model), `settings.json`, the default: a model that gives a setting of its own keeps it whatever the call says for the project. **Which settings:** every one that belongs to a fit (the data selection `Q_MIN`, `Q_MAX`, `SIGMA_SCALE`, `EXCLUDE_Q`, the structure `CHAINS`, `MODEL`, `ADD_HYDROGENS`, `LMAX`, the model, shell, bead and prior settings, the sampler and the MAP search, `RNG_SEED`, `VAL_SIGMA`, `TARGET_ACCEPT`, `N_CHAINS`, `N_ADAPT`, `N_DRAWS`). **Not per model** (`RUN_LEVEL_SETTINGS` in `Settings.jl`, and every `PLOT_*`): `TABLE_SIGFIGS`, `FIGURES_TEX`, `FIGURES_COMPILE`, `FIGURES_FORMATS` and all the `PLOT_*` settings (the look of the figures, `PLOT_COMPARE` and its colours, markers and line width, `PLOT_TUI_SIZES`); naming one in a model's table, or as a keyword of `model_settings`, whatever its value, is an `InvalidSettingsError` that names the file or keyword, the model and the setting (`model-settings.json, model B: PLOT_COMPARE is a setting of the whole run, not of one model`). A test checks the list against the kinds of the catalog, so a new setting has to be classified. An unreadable file, an invalid value, a broken rule (a model's `Q_MIN` above the project's `Q_MAX`) fails the run **before any model starts**, like an invalid `settings.json`; a name in the file that is no model of the project (renamed or removed) is a note in the ERRORS section and is ignored; a keyword that is no setting's, or a table of the wrong shape, is an `ArgumentError` at once. The file is copied into `logs/` with the other inputs. Each model's LOG has a setup row `override_<setting>` (lower case: `override_q_max`) for every setting it was given of its own, a failed model's LOG too, and its `run.json` entry `overrides` lists their names (`["N_CHAINS", "Q_MAX"]`, sorted; empty for none). The buffer and the temperature are the project's: they are not per model, so the `solutes.json` snapshot is made with the project's `PMV_FALLBACK_UNCERT`. The comparison and its workbook stay valid when models were fitted to different data selections: every curve is drawn over its own q range and interpolated onto the measured grid only where it reaches (empty cells elsewhere).
- `n_samples`, `n_adapt`, `sigma`, `rng_seed`, `n_chains`, `retry`, `add_hydrogens` and `lMax` (per model: see "Settings of single models" above) default to the project's settings (`N_ADAPT + N_DRAWS`, `N_ADAPT`, `VAL_SIGMA`, `RNG_SEED`, `N_CHAINS`, `ADD_HYDROGENS`, `LMAX`) and the defaults of `run_model`; the data and structure keywords (`q_min`, `q_max`, `sigma_scale`, `exclude_q`, `chains`, `model`) come from keywords or `settings.json` only (the project's `data.json` does not hold them yet); the seed keywords and the plot style come from the settings too. The other sampler settings are constants the sampler reads and are not applied per run.
- **Reference fit.** The optional folder `<project>/reference-fit/` (called `references/` until 2026-11-09: a project that has only that is still read and its curves are snapshotted under the new name, and a run whose `logs/` has only `references/` still reads it) holds the reference curves the comparison draws: every `.tsv`, `.dat` or `.txt` file (any case of the extension) with two or three numeric columns (q in the units of the project's `data.json`, I, and an optional σ that is read and not used), separated by white space, tabs, commas or semicolons, is one curve named by its file stem (`CRYSOL.tsv` is `CRYSOL`; a taken stem gets `-2`). Blank lines, everything after a `#` and text lines before the first numbers (a header) are skipped. The folder is copied into `logs/reference-fit/` with the other inputs (an interface that took the snapshot itself has put it there) and read from there, q divided by 10 for `"nm-1"`. A file that cannot be read (a cell that is no number, other than 2 or 3 columns, no usable point) is skipped and named in the ERRORS section of `run.LOG` with its line, as a note: it never fails the run or changes its status. Without the folder the comparison has the models and the measured curve alone.
- **The comparison.** After the last model, when `plot_compare` is on (the setting `PLOT_COMPARE`, default `true`) and at least one model finished (one is fine: the data, its fit and the references), `compare_results` draws every finished model, the references and the measured curve into `compare/` (see "The comparison figure"): `plots/<run>_compare.tex`, `<run>_compare.xlsx`, and `plots.txt` (the terminal plot as plain text, also appended as `=== compare ===` to `logs/plots.txt`; printed to the terminal with `ui = :cli`, never with `:tui`; with `:tui` also `plots_<W>x<H>.txt` at the sizes of `PLOT_TUI_SIZES`). `run.json` then has a `compare` entry, `{status: "done"|"failed", files: [paths relative to the run folder, the `plots_<W>x<H>.txt` not among them], models: [names], references: [names], plot_sizes: [{file, width, rows}], error}`; the key is absent when no comparison was made (the switch off, no model finished, an interrupted run). A failure of the comparison is caught like a model's: a note in the ERRORS section, `compare.status` `"failed"` with its `error` line, and the run's status unchanged. A model cannot be named `compare` (its folder would be the comparison's): it gets `compare-2`, as `logs` does.
