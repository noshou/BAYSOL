# Pipeline

The four entry points, re-bound by the package root as `BAYSOL.seed_model`, `BAYSOL.run_model`, `BAYSOL.results`, `BAYSOL.write_log` and `BAYSOL.print_summary`:

```julia
using BAYSOL
seed = BAYSOL.seed_model(src, energy, q, I, σ, pH, σ_pH, solutes) # rebin = 12 per Shannon channel, lMax from the structure
res  = BAYSOL.run_model(seed) # 300 warm-up + 700 draws; run_model(seed, n_samples, n_adapt) to change
BAYSOL.results(res, seed; dir = "out") # terminal plots, pgfplots .tex, and the workbook out/res.xlsx (with `run_log = true` also the run log out/out.LOG, written last)
BAYSOL.write_log(res) # the run log out/out.LOG (what `results(...; run_log = true)` does last)
BAYSOL.print_summary(res) # what a run says at the end (below)
```

## The stages

`seed_model` (every step is a named stage of the `Runtime.StageLog`, cache hits marked):

1. resolve the structure (`MolecularStructure`), look its residue names up (`components`), run the `structure checks` (reused chain ids, duplicate atoms, dummy-like models) and choose the hydrogenation from the content (`classify`);
2. `Hydrogenator`: PROPKA unless the structure is a nucleic acid alone, then pdb2pqr (PARSE, or AMBER for a nucleic acid alone), with modified residues hydrogenated through their parent;
3. the solvent-accessible surface and the diameter `D` of the scatterer cloud (atoms **and** beads), `Utils.Shannon` binning of the curve to `rebin` bins per channel `π/D`, and `lMax = ⌈q_max D⌉`;
4. `Scattering.forward_cache` (the Gram matrix), the priors from the buffer `solutes` (`BulkElectronDensity.ρₑ`), and `Inference.seed_sampler`.

`run_model` calls `Inference.infer` (8 chains, MAP search, harvest, mode pooling, one R̂ retry), drops each chain's warm-up, picks the MAP draw (highest non-divergent `log π`) and computes the quantile intervals and bands. Its result holds everything the workbook reports; developer diagnostics live in the dev tools (`bb diagnose`).

## The figures

`results(result, seed; dir, name = "res", references, style, font, preview = true, io, tex = true, compile = false, formats, run_log = false, ref_chi2)` makes the fit (data with error bars, the posterior bounds band and quantile curves, the MAP curve; log axes), the residuals and the posterior histograms (ρₑ, δρ₁, δρ₂, δρ₃, scale, background, c1, each its own figure `<name>_hist_<parameter>` with the MAP marked), plus one comparison figure per `Reference(name, q, I; q_max)` (data, the reference curve and the MAP curve: the depositor's CRYSOL, FoXS, … fit). Every figure is prepared once as plain arrays (`_curve_data`, `_residual_data`, `_histogram_data`, `_comparison_data`) and drawn three ways:

- **in the terminal** (UnicodePlots, `preview = true`), printed to `io`; it needs nothing installed. It prints the fit (the data in orange and the MAP curve, as log₁₀ q against log₁₀ I(q)) and the residuals, both titled with the MAP's reduced χ²; the residuals are clipped to the 2–98 % range (the title counts the points outside); one orange histogram per parameter has its MAP value in the title. The bounds band and the reference curves are in the `.tex` only;
- **as a pgfplots `.tex`** (PGFPlotsX, `tex = true`): a standalone LaTeX document per figure, written without LaTeX. LaTeX is run only with `compile = true` (to `formats = (:pdf,)`, or `:png`/`:svg`, which also need poppler's `pdftocairo`/`pdftoppm`); a failed run is a warning and the `.tex` stays. It takes about a second per figure, which is why it is off by default;
- **as numbers**: the workbook described below, always written (and, with `run_log = true`, the run log).

**The layout** of the output folder `dir`: the `.tex` files, and what `compile = true` or `bb render-plots` makes from them, are in `dir/plots/`; the workbook `<name>.xlsx` is in `dir`, and so is the run log `<folder name>.LOG` (below), one file for the folder with a section for each run. `name` starts every file name, so several runs can share a folder (`res_fit1`, `res_fit2`). The subfolder name is `PLOT_SUBDIR` in `Pipeline.jl`; a folder is created when something is written to it.

Colours, line widths, marker sizes, the histogram bins, figure sizes and the terminal plots' size are the fields of `PlotStyle` (`PlotStyle(; color_map = "#0000ff", lw_map = 2)`), each defaulting to the `PLOT_*` constant in `Pipeline.jl`; a colour is a name `Colors.parse` reads, a `"#rrggbb"` string or a `(colour, opacity)` tuple.

**The font** of the `.tex` figures is the `font` keyword of `results` (or `PlotStyle(; font = ...)`): the name of any font that LuaLaTeX can find, a `("Text font", "Math font")` pair of `fontspec` names, or `nothing` for the LaTeX default. The default is the pair TeX Gyre PagellaX and TeX Gyre Pagella Math (`PLOT_FONT`; TeX Live packages `newpx` and `tex-gyre-math`). A single name is the text font and leaves the math font at Latin Modern Math; a pair sets both. `font_available("Name")` (also `BAYSOL.font_available`) asks the TeX Live installation, through `luaotfload-tool`, whether a name works and returns `true` or `false`; from the shell, `bb fonts "Name"` does the same and `bb fonts --list` lists every installed family. A font is loaded with `unicode-math`, so a figure with a font compiles only with `lualatex` or `xelatex` (`results` and `bb render-plots` pick one; `pdflatex` cannot), and a font LuaLaTeX cannot find makes the LaTeX run fail with a warning that names it and keeps the `.tex`. With only `pdflatex` installed, use `font = nothing`. The terminal plots and the workbook do not depend on the font.

**The look** of the `.tex` figures: a bold black axis box (`lw_axis`); black ticks pointing inward on all four sides, major and minor (`lw_tick`, `tick_length_cm`, `minor_ticks` between two major ones of a linear axis; a log axis keeps its own); the x tick labels slanted (`xtick_angle`, 45° by default) and hung on bent ticks, each tick leaving the axis straight (`tick_stub_pt`) and then bending (`tick_elbow_pt`) towards its label, which pgfplots cannot do itself, so they are drawn as TikZ (and each plot is clipped on its own, `clip mode=individual`, for them to show outside the axis); the y labels padded from the axis (`tick_label_pad_pt`); the log axes of the fit and comparison figures start and end exactly where the data do; legends in `\footnotesize`. Each histogram has a boxed legend in the top corner over its long tail with the **MAP** (the solid line, in the MAP colour) and **μ** (the dotted line: the middle of the tallest bin, the most sampled part of the posterior), each with its value to enough digits to tell a bin from its neighbour. Every one of these is a `PlotStyle` field defaulting to a `PLOT_*` constant.

**The page** of a figure keeps a border of `PlotStyle`'s `border_pt` (8 pt) round it, so the last tick label, the legend and the axis title are not cut off at the right or top edge.

The time of each figure (its data, preview, `.tex`, LaTeX run; one stage for each histogram) and of the workbook is recorded as stages of the `plot` group of the run's timing log, which is why `results` calls `write_log` last (with `run_log = true`).

## The workbook

`<name>.xlsx` holds every number of a run, one table to a sheet. Sheet and column names are plain ASCII (`rho_e`, `delta_rho_1`, `chi2`), the first row of a sheet names its columns, and every value is a number (a statistic that could not be computed, such as the E-BFMI of a very short chain, is an empty cell, since a spreadsheet has no `NaN`) except the labels in the first column and the text of `form_factor_log`. Every column is as wide as its longest text (up to 80 characters, then wrapped) and the header row is bold. Numbers carry `TABLE_SIGFIGS` (`Pipeline.jl`; 17 by default, every bit of a `Float64`) significant figures. The workbook opens in Excel, LibreOffice and Google Sheets and reads with `pandas.read_excel(path, sheet_name=None)`.

| Sheet | Columns | What it holds |
| --- | --- | --- |
| `run` | `section`, `name`, `value`, `unit`, `meaning` | the run's settings and statistics, one per row, grouped by `section` (`model`, `data`, `sampler`, `convergence`, `output`) and each explained (below) |
| `map` | `parameter`, `value` | the MAP draw: `log_density` (the log posterior density), `rho_e` (buffer electron density, e⁻/Å³), `delta_rho_1`, `delta_rho_2`, `delta_rho_3` (hydration-shell contrasts), `scale`, `bkgrnd_corr` (detector scale and background), `excl_vol_corr` (the profiled excluded-volume correction `c1`), `chi2` (reduced χ² **on the measured points**, `n_raw − 3` degrees of freedom: scale, background, `c1`; the grid CRYSOL and FoXS evaluate, whatever the binning) |
| `quantiles_<interval>` | `parameter`, `quantile_lo`, `quantile_hi`, `bound_lo`, `bound_hi` | the same parameters: the posterior quantile pair (default `2sigma`, the 2.28 and 97.72 percentiles; `run_model(seed; sigma = 1)` or `quantiles = "5-95"` change it, and the `run` sheet gives the percentiles as `quantile_lo_pct` and `quantile_hi_pct`) and the extreme draws that lie inside it |
| `stdev_from_prior` | `parameter`, `z_map`, `z_quantile_lo`, `z_quantile_hi` | for the four parameters with a prior (`rho_e`, `delta_rho_1..3`): how many prior standard deviations (θ-space) the MAP value and the quantile pair lie from the prior mean |
| `modes` | `mode`, `share`, `log_mass`, `log_mass_err`, `chains`, `kept` | only when the chains settled in more than one posterior mode: each mode's share of the posterior mass by bridge sampling, its log mass and error (nats), its number of chains, and whether it keeps draws (`kept` is 0 for a share below 1e-4) |
| `optima` | `optimum`, `share`, `chains`, `started` | only when more than one local optimum carries mass: its share of the Laplace mass, the chains that ended there and how many of them started there |
| `form_factor_log` | `line` | text; only when form-factor parsing logged something |
| `data` | `q`, `I`, `sigma` | the curve the fit saw (Shannon-binned) |
| `model` | `q`, `I_map`, `quantile_lo`, `quantile_hi`, `bound_lo`, `bound_hi` | the MAP curve and the posterior quantile and bounds curves |
| `residuals` | `q`, `I`, `sigma`, `I_map`, `residual` | data, MAP curve and `(I − I_map)/sigma` |
| `hist_<parameter>` | `bin_lo`, `bin_hi`, `count` | the counts of one parameter's histogram (non-divergent draws), seven sheets |
| `draws` | `chain`, `iteration`, `divergent`, `rho_e`, `delta_rho_1..3`, `scale`, `bkgrnd_corr`, `c1`, `chisq_red` | every posterior draw; `divergent` is 1 for a divergent transition |
| `ref_<name>` | `q`, `I` | a reference curve given to `results` |

**The `run` rows**, in order (a row is absent when the run did not record it):

- Sizes: `n_atoms` (atoms of the hydrogenated structure), `lmax` (highest spherical-harmonic degree of the scattering model), `n_q_raw` (measured points), `n_q` (points fitted after binning).
- Sampler settings: `n_samples` (NUTS iterations of each chain, warm-up included), `n_adapt` (the warm-up part), `rng_seed` (reproduces the run), `quantile_lo_pct` and `quantile_hi_pct` (the percentiles of the quantile interval, whatever `sigma` or `quantiles` asked for).
- Shannon binning: `dmax` (Å, the maximum diameter of the atoms and hydration-shell beads), `channels` (q range × `dmax` / π, the number of independent Shannon channels), `rebin_channels` (bins per channel; 0 when the curve was fitted as measured), `rebin_measured` and `rebin_fitted` (points before and after), `rebin_non_positive_dropped` (bins with a non-positive mean that were dropped).
- Sampler statistics: `iterations` (post-warm-up transitions of the pooled chains), `mean_accept` (mean acceptance rate; the target is `DEFAULT_TARGET_ACCEPT`), `tree_depth_avg` and `tree_depth_max`, `mean_n_steps` (leapfrog steps per iteration), `ebfmi` (energy-based fraction of missing information of the worst chain; below about 0.3 the momentum resampling explores poorly), `cavity_frac` (share of the hydration-shell volume carried by cavity beads; near 0 means `delta_rho_3` has no likelihood and its posterior is its prior), `excl_vol_sat` (0, +1 if `c1` sat on its upper bound at the MAP, −1 on its lower), `divergence_rate` (share of divergent transitions).
- Chains: `chains_pooled` (chains whose draws are kept) of `chains_run`, `rhat_max` (worst rank-normalized split R̂ over the four parameters and the log density; above 1.01 the chains have not converged), `ess_min` and `ess_tail_min` (smallest bulk and tail effective sample sizes), then, when they apply, `modes` and `optima` (their counts, with the sheets above), `rewhitened_nats` (log-density gain when the chains found a better basin than the MAP search) and `retry_first_rhat` with `retry_kept` (the first run's R̂ when it was rerun, and 1 if the rerun was kept).

## The run log

`write_log(result; ref_chi2)` writes the run log: the file `<folder name>.LOG` of the output folder, **one file for the folder with a section for each run** (`=== fit3 ===`, named after the workbook, the folder's own name for `res.xlsx`); a second call replaces the run's own section. `results(...; run_log = true)` calls it last (`run_log` is `false` by default; every fitting-test script sets it). It is what a benchmark needs and no more. The first line, `datetime`, stamps the last write (day, 24-hour time, offset from UTC). A section is, in this order: **the run** as flat rows `name`, spaces, a tab, `value` (the cells are padded with spaces to a multiple of 8 and followed by one tab, so the columns line up at any tab width and a line still splits on its tabs): BAYSOL `revision` (with `-dirty` when tracked files have uncommitted changes, so that a run is tied to a commit only when the tree is clean), the `julia` version, the `baysol` version with its release name (`v0.3.0-wʋsg_n_yɩɩda`: the `version` and the `release_name` keys of `Project.toml`, changed together at a release), the `ref_chi2` (the depositor's χ² with its method, if given), the kind of `structure` and the pdb2pqr cache, the atoms, the model and data sizes, the sampler's settings and the seed, the fit (the reduced `chi2` on the measured points, the MAP of `rho_e`, `delta_rho_1..3`, `scale`, `bkgrnd_corr` and `c1`, their `z_` scores from the prior, whether `c1` sits on a bound) and the sampler's health (`divergence_rate`, `n_divergent`, `rhat_max`, `ess_min`, `ess_tail_min`, `ebfmi`, acceptance, tree depth, leapfrog steps and ms/step, the chains, `modes`, `optima`, a retry or a re-whitening); **`--- timing ---`**, the timing table as the reports always showed it, for a person to read: the stages indented by level, with seconds, `% wall`, `(JIT)` and `(GC)` on every row and a `notes` column at the end of the row (short, on the same line, without brackets: what the stage's name carried, such as the NUTS iterations and leapfrog steps or the MAP search's starts, and its own note, such as `cache hit`), the wall clock first (it starts with the process, Linux; elsewhere with the load of BAYSOL, the `startup` being the time before `seed_model`), the `plotting` group, `report write` and `unaccounted`, then `GC:` (the process's total) and the two halves of the wall clock, `fit timing` (everything but the plotting) and `plot timing`; and last **`--- machine ---`** (`machine.os`, cpu and its clock, cores, Julia threads, memory, the load and the free memory when the run started). A number that could not be computed (an E-BFMI of 0/0) has no row. `ref_chi2` is given to `results` as `ref_chi2 = "CRYSOL 1.37"`. Residual statistics (lag-1, runs z) are in no output; `bb diagnose --residuals ID` prints them. The fitting-test scripts under `test/fitting_tests/` are deliberately self-contained examples of these calls.
