BAYSOL_Utils

Shared infrastructure used across the rest of the package: physical/numeric constants, the lazy-value cache primitives, and per-stage run timing.

Constants

Atoms/dummies per pass in Scattering.compute_B_lm.

BAYSOL.BAYSOL_Utils.Constants.DEFAULT_ATOL — Constant

Default absolute tolerance for floating-point equality checks (abs(a - b) < DEFAULTATOL, or isapprox(a, b; atol = DEFAULTATOL)): a few orders of magnitude above Float64 roundoff.

source
BAYSOL.BAYSOL_Utils.Constants.DEFAULT_TEMPERATURE_C — Constant

Default solution temperature, °C, for ρₑ/[`Fitting.ρₑprior](@ref)'s bulk-electron -density calculation. Pass the sample's real temperature instead whenever it is known: water's density is evaluated at it exactly, and the solutes' 25 °C partial molar volumes get a widened uncertainty (see [PMVFRACTIONALEXPANSIBILITY`](@ref)).

source
BAYSOL.BAYSOL_Utils.Constants.DRO12_CONCENTRATION — Constant

Default concentration κ = α + β − 2 of the δρ₁/δρ₂ Beta priors (Fitting.δρ_prior). κ = 14 gives Beta(83/6, 13/6) on DRO_BOUNDS, with its mode at δρ = 1 and SD(δρ) ≈ 1.00. That is the same spread as the Normal(1, 1) δρ₂ prior it replaces.

source
BAYSOL.BAYSOL_Utils.Constants.DRO3_CONCENTRATION — Constant

Default concentration κ = α + β − 2 of the cavity-contrast (δρ₃) Beta prior (Fitting.δρ_prior), stretched onto [−ρ̄ₑ/DRO_UNIT, (φ_max − 1)·ρ̄ₑ/DRO_UNIT]. κ = 1.25 gives Beta(2, 1.25) on u = (δρ₃ − X)/W, with its mode at δρ₃ = 0 (bulk-density cavity water).

source
BAYSOL.BAYSOL_Utils.Constants.DRO_BOUNDS — Constant

CRYSOL3's fitting limits (lo, hi) on the convex/concave shell contrasts δρ₁, δρ₂, in units of DRO_UNIT: "The limits during the fitting are -10 to 2". They are the support of the δρ₁/δρ₂ priors (Fitting.δρ_prior) and of the scaled-logit maps Fitting.Θ/Fitting.Ξ put on them.

source
BAYSOL.BAYSOL_Utils.Constants.DRO_UNIT — Constant

Shell-contrast unit in e·Å⁻³ (CRYSOL's –dro); drok = DROUNIT * δρ_k.

source
BAYSOL.BAYSOL_Utils.Constants.EXCL_VOL_CORR_BOUNDS — Constant

Hard bounds (cmin, cmax) on CRYSOL's excluded-volume correction c1 (Fitting.profiled_corrs), CRYSOL's r₀/r_m. c1 is profiled, not sampled, so these bounds – not a prior – are what stops it from absorbing model misspecification that belongs on the physically meaningful parameters (dns/δρ1-3) instead.

source
BAYSOL.BAYSOL_Utils.Constants.EXCL_VOL_CORR_EPS — Constant

Padding/grid-resolution unit for Fitting.profiled_corrs's c1 search: the search actually runs on (cmin - EXCL_VOL_CORR_EPS, cmax + EXCL_VOL_CORR_EPS) so that landing exactly on cmin/cmax can be distinguished from genuinely wanting to go further (real "saturation"), and the same value is the coarse pre-scan grid's step size.

source
BAYSOL.BAYSOL_Utils.Constants.N_VOL_SHELL — Constant

Default number of points to generate to sample excluded volume. 10.1016/j.bpj.2023.10.034 uses a 16³ voxel grid for each atom; a sphere occupies π/6 of the cube. This works out to roughly (π/6 * 16³) ≈ 2145 points being occupied.

source
BAYSOL.BAYSOL_Utils.Constants.PMV_FRACTIONAL_EXPANSIBILITY — Constant

Fractional partial-molar-volume expansibility, K⁻¹: an upper bound on (∂ϕ°/∂T)/ϕ° used to widen a solute's 25 °C ϕ° uncertainty when the sample is at another temperature, σT = PMVFRACTIONAL_EXPANSIBILITY · ϕ° · |t - 25|.

Derived from the multi-temperature series already bundled with the tables (15-35 °C: sugars, ureas and glycolurils in sources/extractedpmvcandidates.tsv; 18-40 °C: Chalikian et al. 2001's nucleobases/nucleosides, 10.1016/S0301-4622(01)00200-9, the other-T rows of nonbiological.tsv): across those 42 solutes the fractional expansibility spans 0.44-2.96 × 10⁻³ K⁻¹ (median 0.82 × 10⁻³), so 3.0 × 10⁻³ covers every one of them. No electrolyte has multi-temperature data in the tables, so this bound is unverified for salts.

source
BAYSOL.BAYSOL_Utils.Constants.PMV_REFERENCE_TEMPERATURE_C — Constant

Temperature, °C, at which the bundled partial-molar-volume tables are tabulated (see PartialMolarVolumes/README.md: 298.15 K unless a source says otherwise).

source
BAYSOL.BAYSOL_Utils.Constants.PROBE_RADIUS — Constant

Solvent probe radius in Å (water), forwarded to SASA.shell_points.

source
BAYSOL.BAYSOL_Utils.Constants.SHELL_N_TARGET — Constant

Default shell-dummy budget (hydration's ntarget). nothing lets [`SASA.shellpoints`](@ref BAYSOL.SASA.shellpoints) size the cloud from the accessible area (≈ area / SASA.SHELLAREAPERPOINT, floored at SASA.SHELLMINPOINTS); an Int pins it.

source
BAYSOL.BAYSOL_Utils.Constants.SHELL_THICKNESS — Constant

Hydration-shell thickness in Å: how far the perturbed-density water layer extends beyond the solvent-accessible surface. 3.0 is CRYSOL's border-layer default.

source
BAYSOL.BAYSOL_Utils.Constants.φ_max — Constant

Upper bound on the cavity occupancy φ = ρcavity/ρ₀. Water in a cavity can be at most modestly denser than bulk: the densest well-attested hydration water is Merzel & Smith's first layer at 1.15·ρ₀, so φmax = 1.25 leaves margin above it while excluding unphysical over-dense "water" (e.g. the δρ3 = 4, φ ≈ 1.36, seen when δρ3 was unconstrained).

BAYSOL.BAYSOL_Utils.Cache — Module

Thread safe caching primitives.

source
BAYSOL.BAYSOL_Utils.Cache.KeyedCache — Type
KeyedCache{K,V}()

A thread-safe keyed memoization cache: a Dict{K,V} guarded by one ReentrantLock. K/V stay concrete type parameters (never Any) so Base.get! specializes like a bare Dict lookup would.

source
BAYSOL.BAYSOL_Utils.Cache.Lazy — Type

A cache of a value of type T. The thunk runs on the first force.

source
BAYSOL.BAYSOL_Utils.Cache.force — Method
force(c::BAYSOL.BAYSOL_Utils.Cache.Lazy{T}) -> Any

Run c's thunk once, under its lock, then return the stored value on every call.

Arguments

- `c`: the cache to force.
source
BAYSOL.BAYSOL_Utils.Cache.make — Method
make(_::Type{T}, f) -> BAYSOL.BAYSOL_Utils.Cache.Lazy

Build an unforced cache of the T-valued thunk f.

Arguments

- `f`: zero-arg thunk, run once on the first [`force`](@ref).
source
Base.get! — Method
get!(
    f::Union{Function, Type},
    c::BAYSOL.BAYSOL_Utils.Cache.KeyedCache{K, V},
    key
) -> Any

Return the cached value for key, computing it via the zero-arg thunk f and storing it on the first miss. The lookup, compute-on-miss, and store are all done under c's lock, so concurrent callers racing on the same missing key never double-store or observe a torn Dict.

Arguments

  • f: zero-arg thunk, run only on a cache miss for key.
  • c: the cache to look up/store into.
  • key: the lookup key.

Timing

BAYSOL.BAYSOL_Utils.Timing — Module

Wall-clock, JIT-compile and GC time per named stage of a run, for the report's === Timing === section. A StageLog is created when a run starts and is handed down to whatever should be timed; everything is a no-op when the log is nothing.

source
BAYSOL.BAYSOL_Utils.Timing.Stage — Type

One timed stage. group is :static, :sampling or :report; depth 1 is a direct child of its group, 2 a child of the preceding depth-1 stage, and so on. compile and gc are the seconds of seconds spent compiling and in GC. note is free text printed next to the name (e.g. [cache hit]).

source
BAYSOL.BAYSOL_Utils.Timing.StageLog — Type

Stages in execution order (a parent precedes its children), the start time of the run (t0, time_ns(); compile0, the compile counter then), and free-form run facts (info, e.g. lMax, n_samples).

source
BAYSOL.BAYSOL_Utils.Timing.fmt_count — Method
fmt_count(
    n::Integer
) -> Union{Base.AnnotatedString{String}, String}

A count for the timing report: plain below 1000, else thousands with up to two decimals and no trailing zeros (2000 → 2k, 14210 → 14.21k, 1500 → 1.5k).

source

stage_seconds(

A snapshot of the clock, JIT-compile and GC counters. See tock!.

source
BAYSOL.BAYSOL_Utils.Timing.timed! — Method
timed!(
    f,
    log::BAYSOL.BAYSOL_Utils.Timing.StageLog,
    group::Symbol,
    depth::Integer,
    name::AbstractString;
    note
) -> Any

Run f(), recording it as a stage, and return its value. The stage is reserved before f runs, so stages f itself records sit after it (as its children).

source

    name::AbstractString,
    t;
    note

Append the stage that began at t =tick() and ends now, and return its (seconds, compile, gc). A parent stage is pushed before its children by timed!; with tick/tock! push order is finish order.
