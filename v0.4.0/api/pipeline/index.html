Pipeline

The pipeline entry points seed_model, run_model, results, write_log and print_summary, the figure options PlotStyle and Reference, and the result types (src/Pipeline/). The package root re-binds them as BAYSOL.seed_model etc.

BAYSOL.Pipeline — Module

The pipeline entry points: seed_model builds a Inference.Seed from a structure, a measured curve and a buffer, run_model samples it and summarizes the posterior, results draws the figures and writes the workbook of numbers, and write_log writes the run log. BAYSOL.seed_model, BAYSOL.run_model, BAYSOL.results and BAYSOL.write_log are these functions, re-exported by the package root.

BAYSOL.Pipeline.DEFAULT_SIGMA — Constant

Half-width, in σ, of the default posterior interval of run_model: the "quantiles"/"bounds" entries are built from the empirical quantiles that bound the central interval a Normal distribution would have at ±DEFAULT_SIGMA σ (2σ: the 2.28th and 97.72nd percentiles). The quantiles are those of the draws, so the interval is no assumption of a Normal posterior; the σ only says which percentiles. The run sheet records them.

source
BAYSOL.Pipeline.MAX_SIGMA — Constant

The largest sigma run_model accepts. Beyond 3σ (the 0.13th percentile) the quantiles of a run's few thousand draws rest on a handful of draws.

BAYSOL.Pipeline.MAPParams — Type
MAPParams = Dict{String, Float64}

Parameter values at the single MAP (maximum a posteriori, i.e. highest-log-density non-divergent) draw found by run_model, keyed by name:

  • log_density: the MAP draw's log-posterior density.
  • slvnt_e_dns, delta_rho_1, delta_rho_2, delta_rho_3: the shell parameters at that draw (see Inference.Seed for the ξ ordering this is read off of).
  • cavity_shell_frac: fraction of the hydration-shell volume carried by cavity beads (from the Gram matrix at the lowest q). When it is ~0, δρ₃ has essentially no likelihood and its posterior is just its prior.
  • scale, bkgrndcorr: the WLS-fit detector scale/background at that draw.
  • chisqred: the WLS fit's reduced χ² at that draw.
  • z_slvnt_e_dns, z_delta_rho_1, z_delta_rho_2, z_delta_rho_3: how many prior standard deviations (θ-space) the corresponding physical parameter's MAP value sits from its prior mean.

BAYSOL.Pipeline.PlotStyle — Type
PlotStyle(; color_map, color_posterior, …)

The look of the figures of results. Every field is a keyword argument, and each defaults to the PLOT_-prefixed constant of Pipeline of the same name (PlotStyle().color_map is PLOT_COLOR_MAP).

Fields

  • color_map, color_posterior, color_data, color_errorbar, color_band, color_band_resid, color_hist, color_reference: ColorSpecs.
  • lw_map, lw_reference, lw_quantile, lw_quantile_resid, lw_zero_line, lw_errorbar: line widths (pt).
  • markersize, whiskerwidth: the data markers' radius and the error bars' whisker (pt).
  • hist_bins: bins of each posterior histogram.
  • size_cm: (width, curve, residuals, hist) of the figures (cm); hist is the (width, height) of one histogram figure.
  • ylim_log, ylim_lin_pad_frac: the y-ranges of the I(q) and the residuals plots.
  • preview_size: (width, height) of a terminal plot (characters, rows).
  • border_pt: the padding the PDF page keeps round a figure (pt).
  • lw_axis: the line width of the axis box (pt).
  • lw_tick, tick_length_cm, minor_ticks, tick_label_pad_pt: the black axis ticks (line width in pt, major length in cm, the minor ticks between two major ones of a linear axis) and the gap between the y axis and its tick labels (pt).
  • xtick_angle: the angle the x tick labels are turned by (degrees; 0 leaves them level).
  • tick_stub_pt, tick_elbow_pt: each x tick leaves the axis straight for tick_stub_pt and then bends for tick_elbow_pt towards its slanted label (pt).
  • font: the font of the LaTeX output: the name of any font LuaLaTeX can find (the text font; the math font stays Latin Modern Math), a (text font, math font) pair of fontspec names (the default is PLOT_FONT, TeX Gyre PagellaX with TeX Gyre Pagella Math), or nothing for the LaTeX default. font_available says whether a name is usable. A font needs lualatex or xelatex.

BAYSOL.Pipeline._cell — Function

A cell of the workbook: a finite number rounded to TABLE_SIGFIGS significant figures (nothing is rounded at 17 or more, which a Float64 cannot carry); a number that is not finite (a statistic that could not be computed, NaN) is an empty cell, since a spreadsheet has no NaN and would hold it as text. source
BAYSOL.Pipeline._chisq_measured — Method

The reduced χ² of the model curve y (on the fitted grid of sh) against the measured curve: y is interpolated onto the measured q points (Shannon.model_on_raw) and the sum of squared normalized residuals is divided by the number of measured points less the three parameters fitted to the curve by minimization (scale, background and the excluded-volume correction c1). This is the χ² on the grid a program such as CRYSOL or FoXS evaluates, whatever binning the fit used.

source
BAYSOL.Pipeline._chisq_measured_all — Method

Returns

  • Vector{Float64}, one reduced χ² per column.

BAYSOL.Pipeline._curve_bands — Method

The posterior band of the predicted curve at every q: for the draws curves[q, :] of each q, the p_lo and p_hi empirical quantiles and the smallest and largest draw inside them. Each q's draws are sorted once (on a contiguous copy, q's in parallel), and the quantiles and the bounds both read the sorted draws.

Arguments

  • qvals::AbstractVector: the q grid.
  • curves::AbstractMatrix: the predicted curves, Q × draws.
  • p_lo, p_hi: the quantile levels in [0, 1].

Returns

  • (quantiles, bounds): two Q × 3 matrices with the columns (q, low, high).

Exceptions

  • ErrorException if no draw lies between the two quantiles of some q.

BAYSOL.Pipeline._curve_data — Method

The I(q) figure's data: the measured points with positive intensity (the log axes cannot show the others; the fit itself used every point), their error bars' ends (err_lo, err_hi; a plain additive I ± σ interval is not symmetric on a log axis, so σ is propagated into log space by the delta method and the interval is log-symmetric and always positive), the quantile and bounds curves floored at half the smallest intensity (a model can graze 0 at the noise floor, which a log axis cannot show), the MAP curve (non-positive values as NaN), and the y-range centred on the data.

band, quant and map are nothing when the run has no MAP/quantiles (all draws diverged).

BAYSOL.Pipeline._run_sheet — Method

The run sheet: one row for each setting and statistic of the run, with the columns section | name | value | unit | meaning. The section is model, data, sampler, convergence or output, the rows are grouped by it, value is always a number (a flag is 0 or 1; excl_vol_sat is 0, +1 when c1 sat on its upper bound and -1 on its lower one), unit is empty for a pure number, and meaning says in words what the row is and, for a check, what a worrying value is. map_params is nothing when every draw diverged (the rows that depend on the MAP are then left out). BAYSOL.Pipeline.results — Method

The figures of a fit run by run_model, and the numbers behind them. Three figures are made, each from the same prepared data:

  • the fit: the measured points with their error bars, the posterior bounds band and quantile curves, and the MAP curve, on log axes (<name>);
  • the residuals: data minus MAP with the band and quantile curves minus MAP (<name>_residuals);
  • the histograms of the non-divergent draws of ρₑ, δρ₁, δρ₂, δρ₃, scale, background and c1, each its own figure with the MAP value marked (<name>_hist_rho_e, <name>_hist_delta_rho_1, …, <name>_hist_c1);

and one comparison figure per entry of references (data, reference curve, MAP curve; <name>_comparison, or <name>_comparison_<reference name> when there are several).

The files are laid out under dir: the .tex figures (and what is compiled from them) in dir/plots/, and the numbers as one workbook dir/<name>.xlsx; the run's log (timings and what is worth tracking), which write_log writes when run_log = true, is the section of name in dir/<folder name>.LOG. name is the first part of every file name, so several runs can share a folder. Three kinds of output come out of each figure:

  • a terminal preview printed to io (preview = true), made with UnicodePlots, which needs nothing installed;
  • a pgfplots .tex file (tex = true), a standalone document that needs no LaTeX to write. The default does not run LaTeX (it takes about a second per figure); with compile = true each document is also compiled to the formats (:pdf, :png, :svg; this needs a LaTeX engine, and poppler's pdftocairo/pdftoppm for :png/:svg). A failed run is a warning and the .tex stays;
  • the numbers, always written, as one workbook. Sheet and column names are plain ASCII, and every value is a number (a statistic that could not be computed is an empty cell) except the labels in the first column and the text of form_factor_log. The sheets:
    • run: section | name | value | unit | meaning, the run's settings and statistics: model sizes, sampler settings, the Shannon binning, the sampler's diagnostics and the chains' convergence;
    • map: parameter | value, the MAP value of each parameter;
    • quantiles_<interval>: parameter | quantile_lo | quantile_hi | bound_lo | bound_hi, the posterior quantile pair of each parameter and the extreme draws inside it;
    • stdev_from_prior: parameter | z_map | z_quantile_lo | z_quantile_hi, how far the MAP value and the quantile pair of the four prior-carrying parameters lie from the prior mean, in prior standard deviations (θ-space);
    • modes and optima: only when the posterior has more than one mode or optimum;
    • form_factor_log: only when form_factor_log is given or the seed has one;
    • data (q | I | sigma, the fitted curve), model (q | I_map | quantile_lo | quantile_hi | bound_lo | bound_hi), residuals (q | I | sigma | I_map | residual), one hist_<parameter> (bin_lo | bin_hi | count) for each histogram, draws (every draw with its chain, iteration, divergent flag, the four sampled parameters, scale, bkgrnd_corr, c1 and chisq_red) and one ref_<name> (q | I) for each reference curve.
    The README of src/Pipeline/ explains every row of run.

The time of each figure (its data, preview, .tex and LaTeX run), of the summary tables and of writing the workbook is recorded in the run's timing log as stages of the plot group, so the log's timings list them; with run_log it calls write_log last.

Arguments

  • result: what run_model returned.
  • data: the curve the fit saw, (q, I, σ), which is seed.shannon.q, .I, .σ; or the seed itself.
  • dir, name: the output folder (created if missing, with its plots/ subfolder as it is needed) and the first part of the file names.
  • references: References, a vector or a single one.
  • style: a PlotStyle.
  • font: the font of the LaTeX figures, style.font unless given: the name of any font LuaLaTeX can find (the text font), a (text font, math font) pair, or nothing for the LaTeX default (which pdflatex also compiles). The default is TeX Gyre PagellaX with TeX Gyre Pagella Math, and font_available checks a name. A font needs lualatex or xelatex to compile; the terminal plots and the data do not depend on it.
  • preview, io: whether to print the terminal plots, and where.
  • tex, compile, formats: as above.
  • quantile_label: the name of the quantiles sheet's interval (quantiles_<label>); nothing takes the one run_model used (2sigma, 5-95, …).
  • run_log: also write the run's section of the folder's run log (write_log), false by default; the fitting tests set it. The log is then in the files returned.
  • ref_chi2: the reference χ², the depositor's with its method ("CRYSOL 1.37"), which the log prints in the run's section as the ref_chi2 row (only with run_log).
  • form_factor_log, n_atoms: the seed's seed.fw.form_factor_log and seed.fw.n_atoms for the form_factor_log and run sheets; given by themselves when data is a Seed.

Returns

  • The paths of the files written.

Exceptions

  • ArgumentError if data has no positive intensity, its three vectors differ in length, or font is not nothing, a font name or a pair of names.

BAYSOL.Pipeline.run_model — Function

Run NUTS on Inference._logπ starting from seed, returning posterior draws of the physical parameters ξ = (ρₑ, δρ₁, δρ₂, δρ₃), one (scale, bkgrnd_corr) pair and predicted curve per draw, and AdvancedHMC.jl's diagnostics.

The Hamiltonian

HMC adds an auxiliary momentum r ~ N(0, M) (M the mass matrix) and defines a Hamiltonian:

H(θ, r) = -log π(θ) + ½ rᵀM⁻¹r

with potential energy as the negative log-posterior, and Gaussian kinetic energy. Leapfrog integration simulates the system's dynamics forward in time, alternating half-steps in r with full steps in θ:

r ← r - (ε/2)·∇[-log π(θ)]
θ ← θ + ε·M⁻¹r
r ← r - (ε/2)·∇[-log π(θ)]

which needs ∇[log π(θ)] at every step.

Because energy is conserved, leapfrog proposes long, correlated jumps through parameter space far more cheaply than random-walk Metropolis. NUTS removes the need to hand-pick a trajectory length: it grows the leapfrog trajectory by doubling a binary tree of steps, forward and backward in time, until the trajectory starts to double back on itself (a U-turn), then samples from the valid part of that tree.

MAP search and whitening

Before NUTS, Inference.infer finds the mode of the same log π with a multi-start L-BFGS search and takes a central-difference Hessian there. NUTS then samples coordinates w with θ = μ + σ·(ẑ + S·w), in which the posterior is ≈ N(0, I) and the chain starts at the mode. The map is affine, so the target distribution is unchanged; it only puts the adaptation below on the O(1) scales Stan's defaults assume. c1 is profiled out at every evaluation, to EXCL_VOL_CORR_TOL.

Step-size adaptation

δ is the target Metropolis acceptance rate. During the first n_adapt iterations, StepSizeAdaptor tunes the leapfrog step size ε via dual-averaging so the empirical acceptance rate converges to δ; too-small ε wastes computation taking tiny steps, too-large ε causes leapfrog's discretization error (and therefore the rejection rate) to blow up. A gradient that is inconsistent with the value (a loosely profiled c1, see EXCL_VOL_CORR_TOL) has the same effect and is the usual cause of a step size far below what the local curvature allows. MassMatrixAdaptor learns M (here the full parameter covariance, since ρₑ/δρ are physically coupled through the forward model) from the trajectory's sample covariance, starting from the identity in the whitened coordinates.

Arguments

  • seed::Seed: priors, initial point, forward cache, and data.
  • n_samples::Int64=DEFAULT_N_SAMPLES: total number of NUTS iterations (including the n_adapt warm-up steps); the default is 1000.
  • n_adapt::Int64=DEFAULT_N_ADAPT: number of warm-up iterations spent adapting the step size and mass matrix before sampling proper; the default is 300, leaving DEFAULT_N_DRAWS = 700 posterior draws.

Keywords

  • sigma::Union{Nothing,Real}=nothing: the half-width, in σ, of the interval of QuantileResult's "quantiles"/"bounds" entries: the empirical quantiles of the draws at the percentiles a Normal has at ±sigma σ (2 gives 2.28 – 97.72, 1 gives 15.87 – 84.13, 0.5 gives 30.85 – 69.15), 0 < sigma ≤ MAX_SIGMA (3). The interval is that of the draws, not a Normal fitted to them, and the percentiles used are in the run sheet. Neither sigma nor quantiles given means DEFAULT_SIGMA (2).

  • quantiles::Union{Nothing,AbstractString}=nothing: the same interval as a "<lo>-<hi>" range of percentages (integers, 0 ≤ lo < hi ≤ 100), e.g. "5-95", instead of sigma; giving both is an error. The special case "0-0" means no filtering.

  • δ::Real=DEFAULT_TARGET_ACCEPT: target acceptance rate as a percentage, (0, 100) exclusive (validated below); the default, DEFAULT_TARGET_ACCEPT, is 95%.

  • rng_seed::Union{Nothing,Integer}=nothing: the run's random seed (see Inference.infer). To reproduce a fit exactly, pass the rng_seed row of its run log (or the run sheet); nothing picks a fresh one (so Random.seed! before the call also fixes the run).

  • n_chains::Int=Inference.DEFAULT_N_CHAINS: number of NUTS chains (8; chain 1 at the MAP, the others at deterministic distances from it, in mirrored pairs); see Inference.infer. The draws of the chains that did not fail are pooled, and the report gives the split R̂ and ESS of the pool.

  • retry::Bool=true: rerun the sampler once, longer and from derived seeds, when R̂ is above Inference.RETRY_RHAT; see Inference.infer.

  • jitter_seed::Integer=Inference.DEFAULT_JITTER_SEED: seed of the jittered chain starts, separate from rng_seed.

Returns

A 4-tuple (fit, divergencerate, map, curve):

  • fit::Inference.Inferred: the warm-up free posterior, the pooled chains' draws together.
  • divergence_rate::Float64: fraction of fit's draws AdvancedHMC.jl flagged as numerically divergent, [0, 1].
  • map/curve: either both nothing or a MAPResult/QuantileResult pair.

BAYSOL.Pipeline.seed_model — Method

Computes a NUTS seed from given data input:

1.  resolve mol_src to a structure
2.  look the residue names up (`components`) and decide the hydrogenation from
    them (`classify`); if add_hydrogens, add hydrogens with Pdb2pqr: protein only,
    PARSE with PROPKA's pKas (they drive the terminus protonation); nucleotides
    present, AMBER and no PROPKA run if there is no protein; modified
    nucleotides are hydrogenated through the standard residue of their base
3.  compute the accessible surface (the hydration-shell beads), take
    the diameter `D` of the whole scatterer cloud (atoms and beads),
    bin the measured curve to the Shannon channels that diameter allows
    ([`Shannon.shannon_data`](@ref BAYSOL.Utils.Shannon.shannon_data))
    and pick the band limit from it
4.  build the forward-model (gram matrix) on the binned q grid
5.  produce a [`Inference.Seed`](@ref).

Arguments

  • mol_src::MolecularStructure.StructureSource: where to obtain the structure from (MolecularStructure.LocalPathSource, MolecularStructure.PDBIDSource, or MolecularStructure.URLSource).
  • energy::Real: beam energy in eV.
  • qvals::AbstractVector: momentum-transfer grid, Å⁻¹.
  • I_exp::AbstractVector, σ_exp::AbstractVector: measured intensity curve and its per-point standard errors; must be the same length as qvals. Pass the curve as measured over the q range to be fitted: it is binned here, and the bins with non-positive intensity are dropped here.
  • pH::Real: solution pH, drives the titration of Protein, DNA and RNA solutes and Pdb2pqr's hydrogen placement (when add_hydrogens=true).
  • σ_pH::Real: standard uncertainty on pH, propagated through solute titration.
  • solutes::Vector{Solute}: the buffer's components, excluding the measured macromolecule (see Solute).

Keywords

  • rebin::Union{Nothing,Integer} = SHANNON_REBIN: bins per Shannon channel π/D (the bin width is π/(rebin·D), D the diameter of the scatterer cloud), at least this many: a precise curve gets finer bins, until the binning's worst-case bias is below max_bin_bias of its smallest error bar (the number used is the report's rebin line); nothing fits the unbinned curve.
  • max_bin_bias::Real = Shannon.BIN_BIAS_MAX: that bound, 0.3 by default; Inf keeps rebin as given. The data the fit used, the raw data and the choices made are in seed.shannon (Shannon.ShannonInfo).
  • lMax::Union{Nothing,Integer} = nothing: spherical-harmonic band limit for the forward model; nothing takes ceil(q_max·D) (Shannon.auto_lmax), q_max the largest binned q.
  • drop_nonpositive::Bool = true: drop the (binned) points whose intensity is not positive (Shannon.shannon_data).
  • add_hydrogens::Bool=true: whether to run PROPKA + Pdb2pqr at all. false skips both and the forward model runs on the structure exactly as given (heavy-atom-only, unless the file already carries hydrogens). Modified nucleotides are then hydrogenated through their base, an approximation (Hydrogenator).
  • blm_chunk::Unsigned = B_LM_CHUNK: Scattering.compute_B_lm batch size, forwarded to Scattering.forward_cache (results invariant, cost/memory tradeoff only).
  • thickness::Real = SHELL_THICKNESS, probe::Float64 = PROBE_RADIUS, n_target::Union{Nothing,Int} = SHELL_N_TARGET: hydration-shell geometry, forwarded to Scattering.forward_cache.
  • t::Real = DEFAULT_TEMPERATURE_C: sample temperature in °C, forwarded to Inference.seed_sampler.
  • κ_δρ₁₂::Real = κ_δρ₁₂, κ_δρ₃::Real = κ_δρ₃: concentrations of the δρ₁/δρ₂ and δρ₃ priors, forwarded to Inference.seed_sampler.

Returns

  • seed::Inference.Seed, ready to pass to run_model/Inference.infer.

Exceptions

  • MolecularStructure.ComponentError: a residue name is neither in the bundled component table nor in the cache and cannot be downloaded (offline).
  • DomainError: qvals, I_exp, and σ_exp have mismatched lengths, or hold non-finite values, or σ_exp is not positive, or rebin < 1.
  • ArgumentError: qvals/I_exp/σ_exp are empty, or no point has a positive intensity after binning.

BAYSOL.Pipeline.write_log — Method
write_log(result; ref_chi2 = nothing, path = nothing, name = nothing)

Writes the log of a run_model result: what is worth tracking from one run to the next, in the section of the run in the file <folder>.LOG of the output folder of the workbook that results wrote (the section is named after the run, fit3 for res_fit3.xlsx, the folder for res.xlsx; a folder with several runs has one section for each, and a second call replaces the run's own section). The lines are flat, tab-aligned name value rows, then the timing table and the machine:

  • the run: the BAYSOL revision (-dirty if tracked files have uncommitted changes), the Julia version, the BAYSOL version with its release name (v0.3.0-wʋsg_n_yɩɩda), the reference χ² (ref_chi2) if known, the kind of structure and its caches, the atoms, the model and the data, the sampler's settings and the seed;
  • the fit: the reduced χ² on the measured points, the MAP of the parameters and their z-scores from the prior, the cavity fraction;
  • the sampler's health: divergences, R̂, effective sample sizes, E-BFMI, acceptance, tree depth, leapfrog steps, the chains, modes and optima, a retry or a re-whitening;
  • --- timing ---: the timing table as the reports showed it, for a person to read: the stages indented by level with their seconds, share of the wall clock, JIT and GC and a notes column (short, on the same line, no brackets), then the process's GC and the fit and plot timings;
