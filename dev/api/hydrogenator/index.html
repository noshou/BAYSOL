Hydrogenator

Explicit-hydrogen structure generation (src/Hydrogenator/): pdb2pqr hydrogen placement with a choice of force field (PARSE, AMBER, …) and of titration method (PROPKA or none), and the PROPKA pKa prediction behind the first.

BAYSOL.Hydrogenator — Module

Explicit-hydrogen structure generation, through two external command-line tools run as plain subprocesses in an isolated CondaPkg-managed Python environment: pdb2pqr (hydrogen placement, resolve_hydrogens) and propka3 (per-residue pKa prediction, propka_pKas).

How the titratable groups are protonated is a choice, a TitrationMethod: Propka (pdb2pqr's propka mode, pH-driven, protein only) or NoTitration (no pH model). The force field pdb2pqr names the hydrogens and charges with is a second choice, one of FORCE_FIELDS (:parse, except :amber for a nucleic acid alone, see NUCLEIC_FORCE_FIELD). Files are exchanged by path, in the store of MolecularStructure.

source
BAYSOL.Hydrogenator.AMINO_ATOM_ALIASES — Constant

Atoms of a modified amino acid that the parent has under another name: (parent, atom) => name run as. MSE (parent MET) has SE where MET has SD, and SEC (parent CYS) SE for SG; pdb2pqr drops an atom it does not know and builds the missing one at its own, different position (2.4 A from the selenium on SASDH39), so the atom is run as the parent's and gets its name and element back afterwards.

Force field of resolve_hydrogens when none is given.

BAYSOL.Hydrogenator.FORCE_FIELDS — Constant

The force fields pdb2pqr accepts for --ff, which fix the hydrogen names and the partial charges. PARSE has parameters for amino acids only; AMBER and CHARMM also have nucleotides.

source
BAYSOL.Hydrogenator.FRESH_CHAIN_IDS — Constant

The chain ids isolate_chain_ends hands out to the runs it separates, in order.

source
BAYSOL.Hydrogenator.NUCLEIC_FORCE_FIELD — Constant

Force field hydrogenation_choice picks for a structure with nucleic acids and no protein. PARSE and AMBER place the same hydrogens (pdb2pqr's --pdb-output does not depend on the force field), but PARSE is not one-to-one on chimeras such as 246D (an RNA with one deoxy-C, where it aborts on its charge check). Proteins keep PARSE because the terminus flags --neutraln/--neutralc work only with it, and a mixed structure has them.

BAYSOL.Hydrogenator.NUCLEIC_NAME_CLASH — Constant

Residue names that are in the dictionary as something else but are also Amber nucleotide names: RU (ruthenium in the dictionary; uracil in Amber). They are tested by their atoms like unknown names (hydrogenation_choice).

BAYSOL.Hydrogenator.STANDARD_AMINO_ATOMS — Constant

The heavy atoms of the twenty standard amino acids by their PDB names (OXT left out), the atoms a modified amino acid must have to be run as its parent: pdb2pqr invents the heavy atoms a residue lacks (homoserine HSE run as SER would get an OG of its own), so a residue that does not have all of its parent's atoms is not run as it.

BAYSOL.Hydrogenator.NoTitration — Type
NoTitration()

source
BAYSOL.Hydrogenator.Pdb2pqrError — Type

source
BAYSOL.Hydrogenator.Propka — Type
Propka()
Propka(pKas)

pH-driven protonation by PROPKA: pdb2pqr runs with --titration-state-method propka, and each chain's free termini are made neutral or charged from the PROPKA N+/C- pKa records (_terminus_groups). Protein only: PROPKA has no nucleotide model.

pKas are records as propka_pKas returns them for the structure being hydrogenated, assumed and not re-verified; without them they are computed (and cached) on demand.

BAYSOL.Hydrogenator._fraction_deprotonated — Method

Henderson-Hasselbalch fraction of an acid group's titratable atoms that are deprotonated (and therefore, for an acid, charged) at solution pH:

f = 1 / (1 + 10^(pKa - pH))

i.e. 1 - _fraction_protonated(pH, pKa).

source
BAYSOL.Hydrogenator._fraction_protonated — Method

Henderson-Hasselbalch fraction of a base group's titratable atoms that are protonated (and therefore, for a base, charged) at solution pH:

f = 1 / (1 + 10^(pH - pKa))

f -> 1 for pH ≪ pKa, f -> 0 for pH ≫ pKa, and f == 0.5 at pH == pKa.

source
BAYSOL.Hydrogenator._group_protonated — Method

Whether an ionizable group of type ("acid" or "base") carries its titratable hydrogen at solution pH. For a base, protonated ⟺ charged; for an acid, protonated ⟺ neutral. Both reduce to the same rule on the group's charged fraction: charged ⟺ fraction > 0.5. A group sitting exactly at its own pKa (fraction == 0.5) rounds to its uncharged state for both types.

BAYSOL.Hydrogenator._run_pdb2pqr — Method

Run pdb2pqr on in_path with the force field ff (a FORCE_FIELDS entry), the titration arguments titration_args and the global –neutraln/–neutralc flags, writing hydrogenated output to out_path. Modified nucleotides are run as the standard residue of their base and get their own names back (relabel_modified); the non-nucleotide ends of a nucleic chain run under chain ids of their own (isolate_chain_ends). Returns

BAYSOL.Hydrogenator._standard_name — Method

The name of the standard residue pdb2pqr hydrogenates a modified nucleotide of class class (:dna or :rna) and natural base base ("A" "C" "G" "U" "T") as, or nothing.

RNA is A C G U, DNA DA DC DG DT. The two awkward cases were measured with pdb2pqr (PARSE): an RNA component whose base is T (ribothymidine) is U, because RNA has no T residue and the 5-methyl is only an extra heavy atom (kept, its hydrogens not placed, like any hydrogen that exists only in a modification); a DNA component whose base is U is DT, because pdb2pqr accepts the name DU but places no hydrogen on it (1BNA with its thymines renamed: 0 of 48), while as DT the ring hydrogens are placed (the 5-position hydrogen, which a methyl-less residue has, is the one it cannot place).

source
BAYSOL.Hydrogenator._termini_chains — Method

Every chain with at least one N+/C- record in pKa_records – derived from pKa_records alone, no structure file I/O. A chain absent from this list has no free terminus to override and is therefore guaranteed to need no –neutraln/–neutralc flags regardless of what _terminus_groups decides for the chains that do, which is what lets resolve_hydrogens check for a termini conflict up front without needing to parse pdb_path at all in the (overwhelmingly common) no-conflict case.

source
BAYSOL.Hydrogenator._terminus_groups — Method

Partition chains by the pdb2pqr –neutraln/–neutralc flag combination each one individually needs, using _group_protonated per chain's own N+/C- record rather than demanding one global decision across the whole structure. A chain with no free-terminus record of its own (no N+/C- entry – not every chain has a genuinely free terminus) needs no override and lands in the empty-flags group.

Almost always returns a single-entry Dict (every chain needs the same flags); a multi-entry result means different chains round to different protonation states at this pH, which resolve_hydrogens resolves by running pdb2pqr once per group.

Arguments

  • pKa_records: records as returned by propka_pKas; only resname == "N+"/"C-" records are consulted.
  • pH: solution pH, matching the pH propka_pKas's caller intends to use with pdb2pqr.
  • chains: every chain ID in the structure (from the text of the file), so a chain with no N+/C- record still appears in exactly one group.

BAYSOL.Hydrogenator.hydrogenation_choice — Function
hydrogenation_choice(infos, path = nothing) -> NamedTuple

The force field and titration method the residue content of a structure calls for, from the component records of its residue names (MolecularStructure.residue_names):

contentcontentfftitration
amino acids only, or neither:protein:parsePropka
DNA/RNA only:nucleic:amberNoTitration
both:mixed:parsePropka

pdb2pqr's --pdb-output, the only output BAYSOL reads, places the same hydrogens under PARSE and AMBER, so the choice is about robustness, not chemistry: the terminus flags --neutraln/--neutralc exist only with PARSE (AMBER exits with an error), which protein and mixed files need; and PARSE is not one-to-one on chimeras such as 246D, so a nucleic acid alone gets NUCLEIC_FORCE_FIELD. PROPKA has no nucleotide model and the hydrogens of nucleic acids do not depend on pH, so a nucleic acid alone runs no PROPKA. A residue is an amino acid when the dictionary type names a peptide (l-peptide linking, ...) and a nucleotide when its class is :dna or :rna (this includes the Amber names of AMBER_NUCLEIC_NAMES, RG, DA5, ...).

With path, the .pdb the names come from, the legacy ids of the bases ADE GUA CYT URI THY (LEGACY_NUCLEOTIDE_NAMES) count as nucleotides for the residues that carry the sugar-phosphate backbone (legacy_nucleotides_in_file), and there is a safety net for a nucleic acid under names nobody knows: if no component is nucleic, the residues whose names are unknown to the dictionary (and RU, which is ruthenium in it) are tested by their atoms, and one with at least BACKBONE_MIN of the sugar-phosphate BACKBONE_ATOMS is taken as a nucleotide; reason then names it.

Returns

(; content, ff, titration, reason): content as in the table, ff a FORCE_FIELDS entry, titration :propka or :none, and reason the empty string or the safety net's finding.

BAYSOL.Hydrogenator.isolate_chain_ends — Method
isolate_chain_ends(in_path, out_path) -> NamedTuple

Write to out_path a copy of the .pdb at in_path in which the leading and the trailing run of non-nucleic residues of every chain that has nucleotides get a chain id of their own (an id the file does not use, FRESH_CHAIN_IDS). The runs are taken twice, over the residues of a chain id as a whole and over each TER-delimited segment of it that has nucleotides, since which of the two pdb2pqr patches by is not documented; a residue is moved if either says so. Returns

(; changed, back, trailing_amino): whether out_path was written; back maps each fresh chain id to the id it replaces, for restore_chain_ends!; trailing_amino is the set of residue keys (chain, number) (original chain ids) of the isolated trailing residues that are standard amino acids.

Exceptions

  • SystemError: a path cannot be read or written.

BAYSOL.Hydrogenator.modified_hydrogen_deficit — Method
modified_hydrogen_deficit(path, infos) -> NamedTuple

What the hydrogenation did for the modified nucleotides of the hydrogenated .pdb at path: a diagnostic for the timing log, the structure is not changed.

The modified nucleotides (PSU, 5MC, 2MG, ..., HETATM records) are hydrogenated through their base (relabel_modified): pdb2pqr places the hydrogens of the standard residue the base stands for, so the hydrogens that exist only in the modification (a methyl's) are not placed, and a modified residue with no known base gets none. Returns

(; residues, with_base, no_base, expected, placed): the modified residues, how many of them have a known base (and were hydrogenated through it), how many have none, the hydrogens their formulas carry and the hydrogens the file has on them.

Exceptions

  • SystemError: path cannot be read.

BAYSOL.Hydrogenator.plain_letter_dna — Method

The residues of the .pdb at path that are DNA written with RNA letters: a residue named A, C, G or U (RNA in the dictionary) that has no O2' (or O2*) atom, and every residue named T (there is no RNA T). pdb2pqr takes the plain letters as RNA and would add an O2' oxygen to each (and place no hydrogen on a T).

The decision is per residue, on the atoms of that residue alone: a chain that mixes both (a DNA residue in an RNA, as in 246D) is relabelled residue by residue, which is right for a true chimera; the price is that an RNA residue whose O2' is missing from the model is taken for DNA (its chain-mates keep their RNA names). A C G become DA DC DG, and U and T become DT (a uracil without O2' is the DNA-class U of [_standard_name]).

Returns

Dict residue key (chain, number) (columns 22 and 23-27, stripped) => standard DNA name.

BAYSOL.Hydrogenator.restore_dropped_atoms! — Method
restore_dropped_atoms!(in_path, out_path) -> NamedTuple

Compare the heavy atoms of the pdb2pqr input in_path with its output out_path, residue by residue (matched on chain, number and insertion code; a blank input chain id matches the one output residue with that number, or none if there are several). A heavy atom of the input that the output lacks (no output atom of the residue with its name or within 0.01 A of it, and no new output atom within 3 A to pair it with: pdb2pqr renames some atoms (OC1 and OC2 become O and OXT) and its flips move others, which are not losses) is re-attached to its residue in the output, with the input's coordinates, occupancy, B-factor and element and the residue's own name, chain and number (the case: pdb2pqr's 5TERM patch deletes P, OP1 and OP2 of a chain's first nucleotide). When the P of a residue is restored, the H5T pdb2pqr put on its O5' is removed, since the oxygen is bonded to the phosphorus again. Heavy atoms the output has and the input does not (pdb2pqr adds some, OXT for instance) are not touched, only counted and warned about. Residues the output lacks altogether (waters, ligands) are left alone.

The file out_path is rewritten when something is restored.

Returns

(; restored, added, h5t_dropped): the counts.

Exceptions

  • SystemError: a path cannot be read or written.

BAYSOL.Hydrogenator.restore_modified! — Function
restore_modified!(path, plan)

Rewrite the pdb2pqr output at path so that each residue of plan (from relabel_modified) has its original residue name and record type again, hydrogens included. Residues are matched on chain, number and insertion code, which pdb2pqr keeps (a blank chain id of the input excepted: pdb2pqr then names the chain itself, and the match is on number and insertion code alone).

Exceptions

  • SystemError: path cannot be read or written.
