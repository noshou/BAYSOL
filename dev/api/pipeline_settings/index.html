Pipeline: settings

The tunable constants of the pipeline (Params.jl: sample counts, retry and plot defaults) and the settings file (Settings.jl: load_settings, settings_file, seed_keywords, the setting tables and InvalidSettingsError) and the buffer of a project (Buffer.jl: load_buffer and InvalidBufferError). They configure the calls on Pipeline: entry points and Pipeline: results and figures.

BAYSOL.Pipeline.FIGURES_COMPILE — Constant

Default compile of results: run a LaTeX engine on the .tex figures (about a second per figure; needs lualatex, xelatex or pdflatex, and poppler for PNG/SVG). Off by default, and a failed run is a warning.

source
BAYSOL.Pipeline.FIGURES_FORMATS — Constant

Default formats of results when compile is on: the file types made from each .tex, any of :pdf, :png, :svg.

source
BAYSOL.Pipeline.FIGURES_TEX — Constant

Default tex of results: write each figure as a standalone pgfplots .tex file in the output folder's plots/ (LaTeX is not needed for this).

source
BAYSOL.Pipeline.N_ADAPT — Constant

Default warm-up of run_model: NUTS iterations of step-size and mass-matrix adaptation, discarded from the posterior.

source
BAYSOL.Pipeline.N_DRAWS — Constant

Default number of posterior draws of run_model, after the N_ADAPT warm-up iterations.

BAYSOL.Pipeline.PLOT_WIDTH_HEIGHT_CM — Constant

(width, height) in cm of every figure: the I(q) plots, the residuals plot, the comparison plot and each posterior histogram all have exactly this size. 16 cm is the text width of an A4 page with 25 mm margins and of a US Letter page with 1 in margins (16.5 cm), so a figure fits either at full width; the height is 3:2.

BAYSOL.Pipeline.PLOT_XTICK_ANGLE — Constant

The angle (degrees, counter-clockwise) the x tick labels of every figure are turned by, so that long labels (0.3405, 6×10⁻⁶) do not run into each other: they end at their tick and slope up to the left. 0 leaves them horizontal.

BAYSOL.Pipeline.SETTING_CHOICES — Constant

The settings above that hold some of a few fixed choices (any subset, in this order), read by the terminal interface, which shows them as tabs to switch on and off (dev/scripts/harvest_defaults.jl copies them to default_settings.edn).

source
BAYSOL.Pipeline.SETTING_LIMITS — Constant

The limits of each setting above that has one, read by the terminal interface when a user edits a value (dev/scripts/harvest_defaults.jl copies them to default_settings.edn). Each limit is above or below (strict) or at_least or at_most (inclusive). They follow results' check of a PlotStyle: widths, sizes and paddings are not negative. The settings that are tuples are left out.

source
BAYSOL.Pipeline.SETTING_NAMES — Constant

The constants above that are settings, the ones a user may change: the terminal interface shows each on a page of its own, and load_settings accepts a saved value for these and for no other name.

source
BAYSOL.Pipeline.SETTING_PARTS — Constant

The name of each part of the tuple settings above, in order, which the terminal interface shows beside the part when a user edits it. A setting that is a tuple has exactly one name for each of its parts (a named tuple's parts are named by its keys, in their order).

source
BAYSOL.Pipeline.SETTING_RELATIONS — Constant

The rules that tie settings above together, or that a tuple setting must obey, which a set of values must obey as a whole; each is a (rule, setting, ...) and is read by the terminal interface and by load_settings. :all_above: every number of setting is above bound; :ordered: the pair setting has its first number below its second, and above above if there is one; :opacity: setting is a (colour, opacity) pair whose opacity is in 0 to 1.

source
BAYSOL.Pipeline.TABLE_SIGFIGS — Constant

Significant figures of every number in the tables of results: a workbook cell is rounded to this many. The default, 17, is every bit of a Float64 (the number reads back exactly); lower it for shorter files or to drop the noise in the last digits (15 is the most a Float64 is guaranteed to carry).

source
BAYSOL.Pipeline.VAL_SIGMA — Constant

Half-width, in σ, of the default posterior interval of run_model: the "quantiles"/"bounds" entries are built from the empirical quantiles that bound the central interval a Normal distribution would have at ±VAL_SIGMA σ (2σ: the 2.28th and 97.72nd percentiles). The quantiles are those of the draws, so the interval is no assumption of a Normal posterior; the σ only says which percentiles. The run sheet records them.

source

BAYSOL.Pipeline.load_settings — Function
load_settings(path = settings_file()) -> Dict{Symbol,Any}

The value of every setting: the one saved in the settings file path (as the terminal interface writes it) or the default, in the type the default has (an Int, a Float64, a Tuple and so on). A missing file gives the defaults. Every saved value is checked before it is used: its type, the limits and the choices of the setting, a colour that exists, and the rules that tie settings together. Names that are no setting are ignored.

Returns

  • A Dict from setting name (a Symbol) to its value.

Exceptions

  • InvalidSettingsError if the file cannot be read or holds an invalid value; a warning is printed for each problem first. The run that wanted the settings must stop: an invalid setting is reset to its default by the terminal interface.
source
BAYSOL.Pipeline.seed_keywords — Function
seed_keywords(settings = load_settings()) -> NamedTuple

The keywords of seed_model that a setting stands for, from settings (what load_settings returns): thickness (SHELL_THICKNESS), probe (PROBE_RADIUS), κ_δρ₁₂, κ_δρ₃ and pmv_fallback_uncert (PMV_FALLBACK_UNCERT). Pass it on with seed_model(...; seed_keywords(settings)...). The sampler, output and plot settings feed other functions and are not here.

Returns

  • A NamedTuple of the five keywords.

Exceptions

  • KeyError if settings lacks one of the settings (a Dict from load_settings has them all).
source
BAYSOL.Pipeline.setting_kind — Method

The kind of the setting name whose default is v: :bool, :int, :float, :colour, :font, :set (some of the choices of SETTING_CHOICES) or :tuple.

source
BAYSOL.Pipeline.settings_file — Method
settings_file() -> String

The path of the settings file of the user, settings.edn in the BAYSOL folder: the folder BAYSOL_HOME names if that is set to an absolute path, else baysol in the data folder of the system (%LOCALAPPDATA% on Windows, ~/Library/Application Support on macOS, $XDG_DATA_HOME or ~/.local/share elsewhere), as the terminal interface keeps it.

Returns

  • The path; the file need not exist.

Exceptions

  • None.

BAYSOL.Pipeline.InvalidBufferError — Type

The error load_buffer throws when buffer.edn is missing, cannot be read or holds an invalid row; problems has a line for each. Not exported (BAYSOL.Pipeline).

Exceptions

This type is the exception; the fit that asked for the buffer must not go on.

source
BAYSOL.Pipeline.load_buffer — Method
load_buffer(path) -> Vector{Solute}

The solutes of the buffer file path (a project's buffer.edn), in file order, ready for seed_model: the concentrations and their uncertainties are in mM in the file and come back in mol/L. A :nonbiological, :polymer, :dna, :rna or :protein row gives the solute of that name from its :arg; a :custom-nonbio or :custom-polymer row gives a CustomNonBio or CustomPolymer from its snapshot of the custom entry. The ranges of the numbers are not checked here (ρₑ refuses an impossible one). A file without solutes is accepted with a warning (pure water).

Returns

  • A Vector{Solute}.

Exceptions

  • InvalidBufferError if the file is missing (BAYSOL does not guess a buffer), cannot be read, is not a map with a :solutes vector, or holds an invalid row (not a map, an unknown :kind, a missing or mistyped key, :mM not above 0, a negative or missing :sigma-mM, an empty name, 1 to 4 :units not respected, :counts of another length). A warning is printed for each problem first; row numbers start at 1.
