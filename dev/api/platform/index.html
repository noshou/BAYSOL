Platform

The one place that detects the operating system (platform.jl at the root of the repository, the module BAYSOL.Platform). Every package of the repository includes the file by its relative path, so each has its own copy under its own name (Dev.Platform, BAYSOLSetup.Platform, BAYSOLRun.Platform). The guide, the cache layout and the rule for contributors (no Sys.iswindows, Sys.isapple, Sys.islinux or Sys.which elsewhere) are in the development guide; the TypeScript twin is tui/src/core/environment.ts.

BAYSOL.Platform — Module
Platform

Operating-system detection and the helpers that depend on it: os/arch and the is... predicates, the executable name, the PATH separator, a which that sees Windows app-execution aliases, the data, cache, config and runtime folders, the shell, the library search variable and the user id.

BAYSOL.Platform.cache_dir — Method
cache_dir(; env = ENV, home = homedir()) -> String

THE folder that holds BAYSOL's caches (_structures, and _cache for the developer tools; see structure_cache and default_cache): baysol in the cache folder of the system. Where the system has one folder for data and caches (Windows: %LOCALAPPDATA%) that would lie inside the projects folder (<data folder>/baysol) and be swept up with the work, so the caches go to the sibling <data folder>/baysol-cache. The TypeScript twin is cacheFolder in tui/src/core/environment.ts; both tests pin the same paths.

BAYSOL.Platform.default_cache — Method
default_cache(; env = ENV, home = homedir()) -> String

The cache of the developer tools: <cache_dir>/_cache, where the unpacked test fixtures live (its fixtures folder). Not read by the app, and not in install.json (which has no cache field any more). Not changed by BAYSOL_CACHE.

BAYSOL.Platform.find_tool — Method
find_tool(names...; dirs = tool_dirs()) -> Union{String,Nothing}

The path of the first of the programs names that is on the PATH (see which), else the first found in dirs (see tool_dirs); nothing if none. For the tools the developer tools run by their full path, so that an installed 7-Zip or LLVM that is not on the PATH still works. Use which where being on the PATH is the question.

BAYSOL.Platform.free_memory — Method
free_memory() -> Int

The memory, in bytes, that a program can still take without the system swapping out others. Sys.free_memory(), except on macOS: there it counts only the pages that hold nothing at all, a few per cent of the memory of any machine that has been up for a while, because the system keeps the contents of files until someone asks for the memory. The macOS value adds the inactive pages, but no more of them than there are file-backed pages (host_statistics64): an anonymous page is only freed by compressing or swapping it. Sys.free_memory() when the call fails.

structure_cache(; env = ENV, home = homedir()) -> String

The folder the fit reads as BAYSOL_CACHE (downloaded and generated structures, components): $BAYSOL_CACHE when that is an absolute path, else default_structure_cache. The launcher exports install.json's structureCache as BAYSOL_CACHE, which is this same folder for a default install.

BAYSOL.Platform.tmp_dir — Method
tmp_dir(; base = tempdir()) -> String

THE folder of every temporary file BAYSOL makes: baysol in the temporary folder of the system (the system wipes that on its own schedule; nothing in it must matter after the program ends). One folder per process lies below it, see tmp_process_dir; the TUI sweeps the folders of dead processes at start. The TypeScript twin is tmpFolder in tui/src/core/environment.ts; both tests pin the same names.

source

The folder of one process below tmp_dir: <tmp_dir>/<pid>. Not made here.

source
BAYSOL.Platform.tool_dirs — Method
tool_dirs(; env = ENV) -> Vector{String}

The folders in which an installer puts a developer tool without adding the folder to the PATH, the ones that exist: on Windows the 7-Zip and LLVM/bin folders of the Program Files folders (ProgramFiles, ProgramW6432 and ProgramFiles(x86)), on macOS Homebrew's bin folders and its llvm one; none on Linux (the package managers there use the PATH).

source
BAYSOL.Platform.user_id — Method
user_id() -> String

An identifier of the current user that is safe in a file name: %USERNAME% on Windows, the numeric user id elsewhere.

source
BAYSOL.Platform.utc_offset — Function
utc_offset(t = time()) -> Int

The offset of this machine's time zone from UTC, in seconds (east is positive), at the Unix time t, daylight saving included. It is worked out here and not asked of the C library, whose strftime %z prints the NAME of the zone on Windows ("Eastern Standard Time"), not -0500: the local calendar fields of t (Libc.TmStruct), read as if they were UTC, minus t itself (days from the civil date: Howard Hinnant's algorithm). The same on every system.

source
BAYSOL.Platform.utc_offset_text — Function
utc_offset_text(t = time()) -> String

utc_offset as +HHMM or -HHMM (such as -0500), to the minute, the form the logs and reports stamp their times with.

source
BAYSOL.Platform.which — Method
which(name) -> Union{String,Nothing}

The path of the program name on the PATH, or nothing. Sys.which cannot see the programs that Windows runs through an app-execution alias (juliaup's julia.exe in ...\Microsoft\WindowsApps is one: it is a reparse point, not a file), so on Windows a name that Sys.which misses is looked up in the listing of every PATH folder.

within(path, dir) -> Bool

Whether path is dir or inside it (compared on normal paths, any case on Windows).
