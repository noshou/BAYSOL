Pipeline: entry points

The pipeline entry points seed_model and run_model and their result types (src/Pipeline/): seed_model loads the structure and the data and builds the forward cache and priors, run_model samples the posterior, and run_project does all of it for every model of a project folder and writes the run folder. The package root re-binds the entry points (including results, write_log and print_summary) as BAYSOL.seed_model etc. The figures and the workbook are on Pipeline: results and figures, the run log, summary and tables on Pipeline: run log and tables, and the tunable constants and the settings file on Pipeline: settings.

BAYSOL.Pipeline — Module

The pipeline entry points: seed_model builds a Inference.Seed from a structure, a measured curve and a buffer, run_model samples it and summarizes the posterior, results draws the figures and writes the workbook of numbers, compare_results draws the models of one measured curve and the reference curves on one figure, and write_log writes the run log, and run_project does all of it for every model of a project folder and leaves a run folder. BAYSOL.seed_model, BAYSOL.run_model, BAYSOL.results, BAYSOL.compare_results, BAYSOL.write_log and BAYSOL.run_project are these functions, re-exported by the package root.

BAYSOL.Pipeline.MAPParams — Type
MAPParams = Dict{String, Float64}

Parameter values at the single MAP (maximum a posteriori, i.e. highest-log-density non-divergent) draw found by run_model, keyed by name:

  • log_density: the MAP draw's log-posterior density.
  • slvnt_e_dns, delta_rho_1, delta_rho_2, delta_rho_3: the shell parameters at that draw (see Inference.Seed for the ξ ordering this is read off of).
  • cavity_shell_frac: fraction of the hydration-shell volume carried by cavity beads (from the Gram matrix at the lowest q). When it is ~0, δρ₃ has essentially no likelihood and its posterior is just its prior.
  • scale, bkgrndcorr: the WLS-fit detector scale/background at that draw.
  • chisqred: the WLS fit's reduced χ² at that draw.
  • z_slvnt_e_dns, z_delta_rho_1, z_delta_rho_2, z_delta_rho_3: how many prior standard deviations (θ-space) the corresponding physical parameter's MAP value sits from its prior mean.

BAYSOL.Pipeline.seed_model — Method

Computes a NUTS seed from given data input:

0.  keep the part of the measured curve to fit (`q_min`, `q_max`, `exclude_q`) and
    scale its errors (`sigma_scale`)
1.  resolve mol_src to a structure (the `model` of it, and only its `chains`)
2.  look the residue names up (`components`) and decide the hydrogenation from
    them (`classify`); if add_hydrogens, add hydrogens with Pdb2pqr: protein only,
    PARSE with PROPKA's pKas (they drive the terminus protonation); nucleotides
    present, AMBER and no PROPKA run if there is no protein; modified
    nucleotides are hydrogenated through the standard residue of their base
3.  compute the accessible surface (the hydration-shell beads), take
    the diameter `D` of the whole scatterer cloud (atoms and beads),
    bin the measured curve to the Shannon channels that diameter allows
    ([`Shannon.shannon_data`](@ref BAYSOL.Utils.Shannon.shannon_data))
    and pick the band limit from it
4.  build the forward-model (gram matrix) on the binned q grid
5.  produce a [`Inference.Seed`](@ref).

Arguments

  • mol_src::MolecularStructure.StructureSource: where to obtain the structure from (MolecularStructure.LocalPathSource, MolecularStructure.PDBIDSource, or MolecularStructure.URLSource).
  • energy::Real: beam energy in eV.
  • qvals::AbstractVector: momentum-transfer grid, Å⁻¹.
  • I_exp::AbstractVector, σ_exp::AbstractVector: measured intensity curve and its per-point standard errors; must be the same length as qvals. Pass the curve as measured: the part to fit is chosen here (q_min, q_max, exclude_q), it is binned here, and the bins with non-positive intensity are dropped here.
  • pH::Real: solution pH, drives the titration of Protein, DNA and RNA solutes and Pdb2pqr's hydrogen placement (when add_hydrogens=true).
  • σ_pH::Real: standard uncertainty on pH, propagated through solute titration.
  • solutes::Vector{Solute}: the buffer's components, excluding the measured macromolecule (see Solute).

Keywords

  • rebin::Union{Nothing,Integer} = SHANNON_REBIN: bins per Shannon channel π/D (the bin width is π/(rebin·D), D the diameter of the scatterer cloud), at least this many: a precise curve gets finer bins, until the binning's worst-case bias is below max_bin_bias of its smallest error bar (the number used is the report's rebin line); nothing fits the unbinned curve.

  • max_bin_bias::Real = Shannon.BIN_BIAS_MAX: that bound, 0.3 by default; Inf keeps rebin as given. The data the fit used, the raw data and the choices made are in seed.shannon (Shannon.ShannonInfo).

  • lMax::Union{Nothing,Integer} = LMAX: spherical-harmonic band limit for the forward model (the setting LMAX); nothing, the default, takes ceil(q_max·D) (Shannon.auto_lmax), q_max the largest binned q; an integer pins it.

  • drop_nonpositive::Bool = true: drop the (binned) points whose intensity is not positive (Shannon.shannon_data).

  • add_hydrogens::Bool = ADD_HYDROGENS: whether to run PROPKA + Pdb2pqr at all (the setting ADD_HYDROGENS, true by default). false skips both and the forward model runs on the structure exactly as given (heavy-atom-only, unless the file already carries hydrogens). Modified nucleotides are then hydrogenated through their base, an approximation (Hydrogenator).

  • blm_chunk::Unsigned = B_LM_CHUNK: Scattering.compute_B_lm batch size, forwarded to Scattering.forward_cache (results invariant, cost/memory tradeoff only).

  • thickness::Real = SHELL_THICKNESS, probe::Float64 = PROBE_RADIUS, n_target::Union{Nothing,Int} = nothing: hydration-shell geometry, forwarded to Scattering.forward_cache.

  • t::Real = DEFAULT_TEMPERATURE_C: sample temperature in °C, forwarded to Inference.seed_sampler.

  • κ_δρ₁₂::Real = κ_δρ₁₂, κ_δρ₃::Real = κ_δρ₃: concentrations of the δρ₁/δρ₂ and δρ₃ priors, forwarded to Inference.seed_sampler.

  • pmv_fallback_uncert::Real = PMV_FALLBACK_UNCERT: uncertainty, cm³ mol⁻¹, of a non-biological solute whose row of the partial-molar-volume table states none (default: the harvested mean of the table's stated ones, NONBIO_MEAN_UNCERTAINTY). Not recommended to change; it is recorded in the run log. Forwarded to Inference.seed_sampler.

  • bounds_δρ₁₂ = BOUNDS_δρ₁₂, mode_δρ₁₂ = MODE_δρ₁₂: the support (low, high) of the δρ₁/δρ₂ priors (-10, 2) and their mode (1), in units of 0.03 e⁻/Å³; the mode must lie strictly inside the bounds.

  • φ_max = φ_max: the upper bound of the cavity occupancy (1.25), which sets the support of the δρ₃ prior.

  • excl_vol_corr_bounds = EXCL_VOL_CORR_BOUNDS, excl_vol_corr_eps = EXCL_VOL_CORR_EPS: the hard bounds of the profiled excluded-volume correction c1 ((0.8, 1.3)) and the padding and grid step of its search (0.02, at most the width of the bounds).

  • shell_area_per_point = SHELL_AREA_PER_POINT, shell_min_points = SHELL_MIN_POINTS: Å² of accessible surface each shell bead stands for (4) and the least number of beads (55), forwarded to sasa (n_target pins the number instead).

  • shell_sample = SHELL_SAMPLE, sasa_n_occ = SASA_N_OCC: directions sampled per atom (256) and the witness-pass prefix (104, at most shell_sample), forwarded to sasa.

  • bead_ray_range = BEAD_RAY_RANGE, bead_ray_dirs = BEAD_RAY_DIRS: range in Å (12) and number of directions (64) of the cavity classification of the beads, forwarded to sasa.

  • q_min = Q_MIN, q_max = Q_MAX: the q range fitted, Å⁻¹, both ends included; a point outside it is left out. nothing (the default) is no limit. q_min must be below q_max. The curve the range leaves is the measured curve of the run (seed.shannon): its binning, channels and band limit follow it.

  • sigma_scale = SIGMA_SCALE: the factor (above 0, 1 by default) the measured σ_exp are multiplied by, before the binning.

  • exclude_q = EXCLUDE_Q: ranges ((q_lo, q_hi), ...) of q, Å⁻¹, whose points are left out (both ends included); () by default. Each needs 0 ≤ q_lo < q_hi.

  • chains = CHAINS: the chain ids to keep, ("A", "B"); () (the default) keeps all. The others are removed before the hydrogens are added (MolecularStructure.keep_chains).

  • model::Integer = MODEL: which model of a multi-model structure to use, counted from 1 in file order (1 is the first model whatever its number, the default and what was always read; MolecularStructure.reslove_struct).

The crop, the exclusion and the scale are applied to the measured curve first, before the structure is touched, so a range that leaves fewer than 3 points fails at once; the number of points that remain after the binning must be at least 3 too (the scale and the background are fitted). Waters, ions and ligands are not part of the model (the loader keeps the polymer only), and which alternate location of an atom is used is that of BioStructures (the one of highest occupancy): neither is a keyword.

Every setting of load_settings that the structure, shell and priors depend on is a keyword here: seed_keywords turns the settings into them. The keywords added after pmv_fallback_uncert are checked as load_settings checks the setting of the same name (the lower-case keyword is the setting's name, MAP_N_STARTS → map_n_starts), and a bad value throws the same InvalidSettingsError lines. With every keyword at its default the seed is what it was before they existed. A run that changes one of the data or structure keywords records it (q_min, q_max, sigma_scale, exclude_q, the number of points before and after, structure_model, structure_chains, add_hydrogens, lmax_pinned) in its log and workbook.

Returns

  • seed::Inference.Seed, ready to pass to run_model/Inference.infer.

Exceptions

  • MolecularStructure.ComponentError: a residue name is neither in the bundled component table nor in the cache and cannot be downloaded (offline).
  • DomainError: qvals, I_exp, and σ_exp have mismatched lengths, or pmv_fallback_uncert is not finite and above 0.
  • InvalidSettingsError: bounds_δρ₁₂, mode_δρ₁₂, φ_max, excl_vol_corr_bounds, excl_vol_corr_eps, shell_area_per_point, shell_min_points, shell_sample, sasa_n_occ, bead_ray_range or bead_ray_dirs, q_min, q_max, sigma_scale, exclude_q, chains or model is outside its limits or breaks a rule between them (mode_δρ₁₂ not strictly inside bounds_δρ₁₂, excl_vol_corr_eps above the width of excl_vol_corr_bounds, sasa_n_occ above shell_sample, q_min not below q_max, a range of exclude_q with q_lo not below q_hi), with the line load_settings gives.
  • MolecularStructure.StructureSourceError: model is above the number of models of the structure, or chains names a chain it does not have (the message lists them).
  • ArgumentError: an input is outside its limits (a non-finite or non-positive q, σexp, energy, thickness or κ; a negative `σpHorprobe;rebin,lMax,ntargetorblmchunkbelow 1; a temperature at or below absolute zero), orqvals/Iexp/σexpare empty, or no point has a positive intensity after binning, or fewer than 3 points are left to fit byqmin,qmaxandexclude_q` (before the binning) or by the binning and the dropping of non-positive bins (the message names those keywords).

BAYSOL.Pipeline._chisq_measured — Method

The reduced χ² of the model curve y (on the fitted grid of sh) against the measured curve: y is interpolated onto the measured q points (Shannon.model_on_raw) and the sum of squared normalized residuals is divided by the number of measured points less the three parameters fitted to the curve by minimization (scale, background and the excluded-volume correction c1). This is the χ² on the grid a program such as CRYSOL or FoXS evaluates, whatever binning the fit used.

BAYSOL.Pipeline.run_model — Function

Run NUTS on Inference._logπ starting from seed, returning posterior draws of the physical parameters ξ = (ρₑ, δρ₁, δρ₂, δρ₃), one (scale, bkgrnd_corr) pair and predicted curve per draw, and AdvancedHMC.jl's diagnostics.

The Hamiltonian

HMC adds an auxiliary momentum r ~ N(0, M) (M the mass matrix) and defines a Hamiltonian:

H(θ, r) = -log π(θ) + ½ rᵀM⁻¹r

with potential energy as the negative log-posterior, and Gaussian kinetic energy. Leapfrog integration simulates the system's dynamics forward in time, alternating half-steps in r with full steps in θ:

r ← r - (ε/2)·∇[-log π(θ)]
θ ← θ + ε·M⁻¹r
r ← r - (ε/2)·∇[-log π(θ)]

which needs ∇[log π(θ)] at every step.

Because energy is conserved, leapfrog proposes long, correlated jumps through parameter space far more cheaply than random-walk Metropolis. NUTS removes the need to hand-pick a trajectory length: it grows the leapfrog trajectory by doubling a binary tree of steps, forward and backward in time, until the trajectory starts to double back on itself (a U-turn), then samples from the valid part of that tree.

MAP search and whitening

Before NUTS, Inference.infer finds the mode of the same log π with a multi-start L-BFGS search and takes a central-difference Hessian there. NUTS then samples coordinates w with θ = μ + σ·(ẑ + S·w), in which the posterior is ≈ N(0, I) and the chain starts at the mode. The map is affine, so the target distribution is unchanged; it only puts the adaptation below on the O(1) scales Stan's defaults assume. c1 is profiled out at every evaluation, to EXCL_VOL_CORR_TOL.

Step-size adaptation

δ is the target Metropolis acceptance rate. During the first n_adapt iterations, StepSizeAdaptor tunes the leapfrog step size ε via dual-averaging so the empirical acceptance rate converges to δ; too-small ε wastes computation taking tiny steps, too-large ε causes leapfrog's discretization error (and therefore the rejection rate) to blow up. A gradient that is inconsistent with the value (a loosely profiled c1, see EXCL_VOL_CORR_TOL) has the same effect and is the usual cause of a step size far below what the local curvature allows. MassMatrixAdaptor learns M (here the full parameter covariance, since ρₑ/δρ are physically coupled through the forward model) from the trajectory's sample covariance, starting from the identity in the whitened coordinates.

Arguments

  • seed::Seed: priors, initial point, forward cache, and data.
  • n_samples::Int64=N_ADAPT + N_DRAWS: total number of NUTS iterations (including the n_adapt warm-up steps); the default is 1000.
  • n_adapt::Int64=N_ADAPT: number of warm-up iterations spent adapting the step size and mass matrix before sampling proper; the default is 300, leaving N_DRAWS = 700 posterior draws.

Keywords

  • sigma::Union{Nothing,Real}=nothing: the half-width, in σ, of the interval of QuantileResult's "quantiles"/"bounds" entries: the empirical quantiles of the draws at the percentiles a Normal has at ±sigma σ (2 gives 2.28 – 97.72, 1 gives 15.87 – 84.13, 0.5 gives 30.85 – 69.15), any finite sigma > 0 (there is no upper limit: beyond about 3σ the quantiles of a few thousand draws rest on a handful of draws). The interval is that of the draws, not a Normal fitted to them, and the percentiles used are in the run sheet. nothing means VAL_SIGMA (2).

  • δ::Real=TARGET_ACCEPT: target acceptance rate as a percentage, (0, 100) exclusive (validated below); the default, TARGET_ACCEPT, is 95%.

  • rng_seed::Union{Nothing,Integer}=Inference.RNG_SEED (0): the run's random seed (see Inference.infer). To reproduce a fit exactly, pass the rng_seed row of its run log (or the run sheet); nothing picks a fresh one (so Random.seed! before the call also fixes the run). The default, 0, makes every run reproducible.

  • n_chains::Int=Inference.N_CHAINS: number of NUTS chains (8; chain 1 at the MAP, the others at deterministic distances from it, in mirrored pairs); see Inference.infer. The draws of the chains that did not fail are pooled, and the report gives the split R̂ and ESS of the pool.

  • retry::Bool=Inference.RETRY (true; a CLI and developer switch, not a setting): rerun the sampler once, longer, always adapting again and from derived seeds, when the run does not count as converged (R̂ above Inference.RHAT_OK, an ESS below Inference.ESS_MIN, or either not computable); see Inference.infer. If the run is still not converged, run_model throws Inference.NotConvergedError and nothing is reported. retry = false skips both the rerun and the error: the run is only flagged in its summary.

  • retry_n_adapt::Integer=Inference.RETRY_N_ADAPT, retry_n_draws::Integer= Inference.RETRY_N_DRAWS (2000, 2000): warm-up and post-warm-up iterations per chain of the rerun.

  • chain_start_radii=Inference.CHAIN_START_RADII ((4, 10, 20)): the distances from the MAP, in posterior standard deviations, at which the mirrored pairs of chains start; pairs beyond the list reuse the last radius.

  • optimum_chain_cap::Integer=Inference.OPTIMUM_CHAIN_CAP (6), optimum_min_chains::Integer=Inference.OPTIMUM_MIN_CHAINS (2), optimum_chain_radius::Real=Inference.OPTIMUM_CHAIN_RADIUS (4), optimum_chain_fraction::Real=Inference.OPTIMUM_CHAIN_FRACTION (0.5): how many chains an optimum that carries mass should have, how many extra chains are started in all, and what counts as a chain being at an optimum (the share of its draws within the Mahalanobis radius).

  • map_max_iter::Integer=Inference.MAP_MAX_ITER (500), map_n_starts::Integer= Inference.MAP_N_STARTS (64), map_f_successive::Integer=Inference.MAP_F_SUCCESSIVE (3), map_optima_kept::Integer=Inference.MAP_OPTIMA_KEPT (8): the MAP search's iteration cap and number of L-BFGS starts, the successive small decreases that end a start, and the optima kept for comparison by Laplace mass.

  • map_jitter_radii=Inference.MAP_JITTER_RADII ((3, 6, 12)), map_jitter_directions::Integer=Inference.MAP_JITTER_DIRECTIONS (2), map_jitter_max_optima::Integer=Inference.MAP_JITTER_MAX_OPTIMA (4), map_jitter_within_nats::Real=Inference.MAP_JITTER_WITHIN_NATS (15): the jittered starts around the optima found.

  • basin_restart_nats::Real=Inference.BASIN_RESTART_NATS (2): how far above the MAP a draw must be for the sampler to re-whiten at its basin.

  • harvest_cover::Integer=Inference.HARVEST_COVER (16), harvest_divergent::Integer=Inference.HARVEST_DIVERGENT (8): the draws, and divergent draws, from which L-BFGS looks for optima the search missed.

Every setting of load_settings that the sampler depends on is a keyword here (n_samples and n_adapt are the positional arguments): run_keywords and run_arguments turn the settings into them. The keywords from retry_n_adapt on are those of Inference.SamplerOptions; they are checked as load_settings checks the setting of the same name (the keyword is the setting's name in lower case, MAP_N_STARTS → map_n_starts) and a bad value throws the same InvalidSettingsError lines.

Returns

A 4-tuple (fit, divergencerate, map, curve):

  • fit::Inference.Inferred: the warm-up free posterior, the pooled chains' draws together.
  • divergence_rate::Float64: fraction of fit's draws AdvancedHMC.jl flagged as numerically divergent, [0, 1].
  • map/curve: either both nothing or a MAPResult/QuantileResult pair.

Exceptions

  • Inference.NotConvergedError if the run is not converged after its retry (retry = true): nothing is returned, so nothing can be reported.
  • DomainError if n_adapt < 1, n_samples ≤ n_adapt, sigma is not a finite number above 0, or δ is not strictly inside (0, 100); n_chains < 1.
  • InvalidSettingsError if one of the keywords from retry_n_adapt on is outside its limits (a count below its least, a radius at or below 0, a fraction outside (0, 1], a chain_start_radii or map_jitter_radii that is not three positive numbers).

BAYSOL.Pipeline.run_project — Method
run_project(project_dir; temperature, ui = :cli, run_dir = nothing, ...) -> NamedTuple

Fits every model of a project, in this one process, and writes what came out as a run folder, <project_dir>/runs/<stamp>/ (stamp is the local time, the zone label, its offset from UTC and the date, (HH-MM-SS-mmm_TZ_±HHMM)_(YYYY-MM-DD)):

run.json            status, pid, host, times, heartbeat, versions, the models (each
                    with its `plot_sizes` and `overrides`), timings and, once made,
                    the `compare` entry
logs/               settings.json buffer.json solutes.json data.tsv data.json
                    models.json model-settings.json (if the project has one)
                    reference-fit/ (the snapshot the run read), run.LOG, plots.txt
<model>/            one folder per model (its file stem; a clash gets `-2`, ...)
    <model>.LOG     the log of that fit ([`write_log`](@ref)); `status` and `error`
                    rows instead of a fit for a model that failed
    output/         the workbook `<model>.xlsx`, `plots.txt`, with `ui = :tui` the same
                    plots at the other sizes, `plots_<W>x<H>.txt`, and the `.tex`
                    figures (in `output/plots/`; rendered files too when the
                    settings compile)
compare/            the combined comparison of the models and the references
                    (compare_results): <run>_compare.xlsx, plots.txt (with `:tui`
                    also plots_<W>x<H>.txt) and plots/<run>_compare.tex; made when
                    `plot_compare` is on

The project folder holds settings.json (what load_settings reads: the settings of this project), buffer.json (the solutes with the pH and its σ, see load_buffer and load_buffer_ph), data.tsv and data.json (the curve, three columns q, I, sigma; units "nm-1" or "A-1", the X-ray energy in eV; the other keys are ignored), models/ (.cif and .pdb files) and, optionally, reference-fit/ (named references/ before 2026-11-09; a project that has only that is still read, and its curves are snapshotted under the new name): every .tsv, .dat or .txt file in it with two or three numeric columns (q in the units of data.json, I, an optional σ that is read and not used) is a reference curve named by its file stem, drawn on the comparison figure (comments #, blank lines and text lines before the first numbers are skipped; a file that cannot be read is a note in the ERRORS section and is skipped, never a failed run). The inputs are copied into logs/ first and the run reads only the copies, so editing the project while it runs changes nothing; a file that is already in logs/ (a caller that took the snapshot itself) is used as it is. temperature (°C, no uncertainty) is the buffer's, and with the pH, its σ and the energy it is a row of every LOG (temperature_c, ph, sigma_ph, energy_ev).

After the last model, when the setting PLOT_COMPARE (the keyword plot_compare, true by default) is on and at least one model was fitted, the run makes ONE combined figure of the measured curve, the fitted curve of every model that finished and the reference curves (compare_results) into <run>/compare/, and records it in run.json as the compare entry: status (done or failed), files (relative to the run folder), the models and references drawn and an error line. Its failure is caught like a model's (a note in the ERRORS section) and does not change the run's status; the key is absent when no comparison was made.

ui = :cli prints the plots to the terminal as well as writing them; ui = :tui never prints them (they are in plots.txt only), for a caller that shows the output live, and writes them at the sizes of the setting PLOT_TUI_SIZES too (the keyword plot_tui_sizes): plots_<W>x<H>.txt next to plots.txt for every model and for the comparison, in the same layout, so a viewer shows the largest that fits its window. Each model's run.json entry (and the compare entry) lists them as plot_sizes, [{file, width, rows}] (file relative to the run folder, width the widest line in terminal cells, rows the lines of the tallest plot); the list is empty with :cli.

Settings of single models. The project's model-settings.json gives some settings to single models: {"<model>": {<sheet>: {"<SETTING>": {"value": ...}}}}, the shape of settings.json for each model, named by its file stem. The keyword model_settings, a Dict or NamedTuple from a model name to a Dict or NamedTuple of keywords ((; crambin = (; q_max = 0.3, n_chains = 8))), does the same for a caller and wins over the file. A model is fitted with the settings of the project (the defaults, then settings.json, then the keywords of this call) and, on top of them, its own: the order of strength is the model_settings keyword, the file, the keywords of the call, settings.json, the default. Every setting that belongs to one fit may be given for a model (the data selection, the structure, the model, shell, bead and prior settings, the sampler, LMAX, RNG_SEED, VAL_SIGMA, TARGET_ACCEPT, N_CHAINS, N_ADAPT, N_DRAWS, ...), not the settings of the whole run (PLOT_*, TABLE_SIGFIGS, FIGURES_*: RUN_LEVEL_SETTINGS), which are refused with an InvalidSettingsError that names the setting and the model. An invalid or unreadable file, a value out of its limits or a broken rule between settings fails the run before any model starts, as an invalid settings.json does. A name that is no model of the project is a note in the ERRORS section and is ignored. Each model's LOG has a row override_<setting> for every setting it was given of its own, its run.json entry overrides (the names), and the comparison draws every model over its own q range. The file is copied into logs/ like the other inputs. The log, the summary of each fit and the sampler's own output always go to stdout and stderr, and are copied into logs/run.LOG, which ends with a --- result --- block and, if anything failed, an === ERRORS === section with each message and its stack.

Failures do not stop the loop. An exception while fitting a model (an unknown element or radius, a residue that cannot be resolved, a run that did not converge, ...) is caught, written to the ERRORS section, the model is failed in run.json and the next model starts; the run ends failed if anything failed (an invalid input, such as a buffer or a setting, fails the run before any model) and done if all models did. An InterruptException (Ctrl-C), a SIGTERM (an exit hook: Julia prints a stack for the signal, which is no error of the run) or, with watch_stdin, the end of the standard input (the caller closed or died: the process exits, none is left over) ends the run as aborted: the model that was running is aborted, the rest skipped, the files are finished and nothing more is done.

run.json is rewritten by this function alone, atomically (a temporary file renamed over it), at every change and every heartbeat seconds (10 by default: its heartbeat is the time of the last rewrite); a run counts as live while status is running and the heartbeat is under a minute old. Without run_dir the folder is claimed here: a non-recursive mkdir of the stamp (when it exists, the next millisecond), after a check that no run of the project is live. A caller that claims the folder itself, under its own lock, passes it as run_dir.

Arguments

  • project_dir: the project folder.

Keywords

  • temperature::Real: the buffer's temperature, °C (required; above absolute zero).
  • ui::Symbol = :cli: :cli or :tui.
  • run_dir = nothing: an existing, already claimed run folder to use instead of claiming one.
  • n_samples, n_adapt, sigma, rng_seed, n_chains, retry: for run_model; by default the settings N_ADAPT + N_DRAWS, N_ADAPT, VAL_SIGMA, RNG_SEED and N_CHAINS of the project's settings.json, and the default of retry. rng_seed = :settings (the default) takes the setting, an integer that value and nothing a fresh seed (which each model's LOG records).
  • add_hydrogens = nothing, lMax = :settings: for seed_model; by default the settings ADD_HYDROGENS and LMAX of the project (true, automatic). A Bool and an integer (or nothing, automatic) override them.
  • Every other setting, as a keyword that overrides the project's settings.json (all default to nothing: take the setting). The value is checked as load_settings checks the setting (the relations between settings too), and the run fails before any model, with an inputs error, if it is not valid; a keyword that is no setting is an ArgumentError at once.
    • for seed_model, the data and structure: q_min, q_max (nothing is no limit and clears a saved one; the default :settings takes the saved one), sigma_scale, exclude_q, chains, model (from the keywords only: the data of the project, data.json, does not hold them yet);
    • for seed_model: thickness, probe, κ_δρ₁₂, κ_δρ₃, pmv_fallback_uncert, bounds_δρ₁₂, mode_δρ₁₂, φ_max, excl_vol_corr_bounds, excl_vol_corr_eps, shell_area_per_point, shell_min_points, shell_sample, sasa_n_occ, bead_ray_range, bead_ray_dirs (the seed_keywords);
    • for run_model: n_draws (N_DRAWS; n_samples wins if given), δ, retry_n_adapt, retry_n_draws, chain_start_radii, optimum_chain_cap, optimum_min_chains, optimum_chain_radius, optimum_chain_fraction, map_max_iter, map_n_starts, map_f_successive, map_optima_kept, map_jitter_radii, map_jitter_directions, map_jitter_max_optima, map_jitter_within_nats, basin_restart_nats, harvest_cover, harvest_divergent (the run_keywords);
    • for results: tex, compile, formats, table_sigfigs, plot_dir (FIGURES_DIR: the figures of each model are also copied to <plot_dir>/<project>/<run>/<model>/), latex_compiler (FIGURES_COMPILER) and style, a PlotStyle that replaces the one the PLOT_* settings describe (the results_keywords);
    • for the run: plot_compare (PLOT_COMPARE), whether the combined comparison is made; its colours, markers and line width are the style's colors_compare, markers_compare and lw_compare; plot_tui_sizes (PLOT_TUI_SIZES), the sizes of the terminal plots that :tui also writes, ((width, height), ...) (checked as the setting is: each at least 24 by 3 and at most 400 by 100, growing in both).
  • model_settings = nothing: the settings of single models, a Dict or NamedTuple from a model name to a Dict or NamedTuple of the keywords above (see "Settings of single models").
  • watch_stdin::Bool = (ui === :tui): end the run as aborted when stdin_io reaches its end. Off for :cli, where a terminal's end of file is a user's choice and a closed standard input (a service, /dev/null) must not stop a run.
  • stdin_io::IO = stdin: the stream that watch_stdin watches.
  • exit_on_eof::Bool = true: when that stream ends, finish the files as aborted and exit the process at once (code 130). false only stops the run after the model that is being fitted (a caller that is not a process of its own).
  • heartbeat::Real = 10.0: seconds between two heartbeats.
  • tee::Bool = true: copy stdout and stderr into run.LOG (off, the log has the header and result only: for a caller that has redirected them itself).
  • fit::Function: the function that fits one model and writes its folder (a seam for the tests; the default is the real fit). A NamedTuple with a result field that it returns is that model's result, which the comparison draws.

Returns

  • (; dir, status, models): the run folder, the final status as a Symbol (:done, :failed or :aborted) and a (name, status) pair for each model.

Exceptions

  • ArgumentError for a missing project_dir, a ui that is neither :cli nor :tui, a temperature that is not above absolute zero, or a run_dir that is not a folder; this before anything is written.
  • ArgumentError also for a model_settings that is not a table of tables or that names a keyword that is no setting's.
  • ErrorException (a run is in progress (pid N)) when no run_dir was given and a run of the project is live.
  • Base.IOError when a run folder cannot be made. Nothing else escapes: the rest is in run.json and run.LOG.
