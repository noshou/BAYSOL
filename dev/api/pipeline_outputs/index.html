Pipeline: run log and tables

The run's other outputs (src/pipeline/): writeLog and the timing table (log.jl), printSummary and the run sheet (summary.jl) and the workbook writers (tables.jl). The figures are on Pipeline: results and figures and the entry points on Pipeline: entry points.

BAYSOL.Pipeline._fmtSeconds — Method

Seconds as the timing table prints them: two decimals, or, below 0.01 s, in scientific notation with two significant figures (3.0e-03), so a stage that took a few milliseconds is not shown as a block of zeros. Exactly 0 prints as 0.

source
BAYSOL.Pipeline._logCell — Method

A number as a log cell: an integer as it is, a float to 6 significant figures.

source
BAYSOL.Pipeline._logCount — Method

A count with a k or M suffix (69.91k) as a number.

source
BAYSOL.Pipeline._logMachine — Method

The machine the run was made on, as the last rows of its section ([name, value] pairs): the system, the processor and its clock, the cores, the Julia threads, the memory, and the load and the free memory when the run started (a busy machine spoils a timing).

source
BAYSOL.Pipeline._logRevision — Method

The short git revision of the BAYSOL source tree, with -dirty when it has uncommitted changes to tracked files, unknown when it is not a git checkout.

source
BAYSOL.Pipeline._logStage — Method

The first stage of log whose name starts with prefix (its name and note), or nothing.

source
BAYSOL.Pipeline._logStamp — Method

The stamp of a write of the log: the day, the time (24 hours) and the offset from UTC (ex: 27-10-2026 14:09:33 +0200).

source
BAYSOL.Pipeline._logStats — Method

The rows of the setup, fit and sampler sections of a run's log ([name, value] pairs).

Returns

BAYSOL.Pipeline._logVersion — Method

The version of BAYSOL as the log prints it, v<version>-<release name> (v0.3.0-wʋsg_n_yɩɩda; just v<version> when RELEASE_NAME is empty), the version of its Project.toml; unknown when that cannot be found.

BAYSOL.Pipeline._stageAndNote — Method

A stage's name without what it carries in parentheses (NUTS (8k iters, 69.91k leapfrog)) or after a comma (optima from the draws, 0 extra chains), and that detail joined to the stage's own note, with the brackets and parentheses that only set it off dropped.

Returns

  • (stage, notes).
source
BAYSOL.Pipeline._tabLines — Method

Lays out rows (each a vector of cells) as lines of tab-separated cells that line up in any viewer: a cell that has another after it is padded with spaces to the width of its column, a multiple of 8 that leaves room for the widest cell, and followed by one tab. At a tab width of 2, 4 or 8 the next cell starts in the same column on every line, and a line still splits on its tabs (the cells keep their padding, which a reader trims).

source
BAYSOL.Pipeline._timingTable — Method

The timing table of a run: one row (name, depth, secs, pct, jit, gc, note) for the wall clock (depth 0), then for each stage (a group row sums its depth-1 stages), then report write and unaccounted; and the totals gc (the process's GC time), fit (everything but the plotting) and plot. The wall clock runs from the start of the process (the startup, Linux) through seedModel to now. tReport is the tick taken when the table began, so report write is the time spent writing before it.

source
BAYSOL.Pipeline._timingText — Method

The timing table of a run (see _timingTable) as lines of text, for a person to read: a header, then a row for the wall clock and each stage, indented two spaces for each level, with its seconds, its share of the wall clock, its JIT and GC seconds (every row has all four) and its notes in a column of their own, short and on the same line (what the stage's name carried in parentheses and its own note, without brackets, see _stageAndNote). The last three lines are the process's GC time and the two halves of the wall clock, fit timing (everything but the plotting) and plot timing.

source
BAYSOL.Pipeline._updateLog — Method

Replaces the section title of the log file path with lines (or adds it at the end), keeping the others as they are, and stamps the file with the time of the write on its first line. The file is written next to its final name and then renamed.

BAYSOL.Pipeline.writeLog — Method
writeLog(result; refChi2 = nothing, path = nothing, name = nothing)

Writes the log of a runModel result: what is worth tracking from one run to the next, in the section of the run in the file <folder>.LOG of the output folder of the workbook that results wrote (the section is named after the run, fit3 for res_fit3.xlsx, the folder for res.xlsx; a folder with several runs has one section for each, and a second call replaces the run's own section). The lines are flat, tab-aligned name value rows, then the timing table and the machine:

  • the run: the BAYSOL revision (-dirty if tracked files have uncommitted changes), the Julia version, the BAYSOL version with its release name (v0.3.0-wʋsg_n_yɩɩda), the reference χ² (refChi2) if known, the kind of structure and its caches, the conditions (temperatureC, ph, sigmaPh, energyEv: what seedModel was given), the data and structure choices that differ from the defaults (qMin, qMax, sigmaScale, excludeQ, the points before and after, structureModel, structureChains, addHydrogens, lmaxPinned), the atoms, the model and the data, the sampler's settings and the seed;
  • the fit: the reduced χ² on the measured points, the MAP of the parameters and their z-scores from the prior, the cavity fraction;
  • the sampler's health: divergences, R̂, effective sample sizes, E-BFMI, acceptance, tree depth, leapfrog steps, the chains, modes and optima, a retry or a re-whitening;
  • --- timing ---: the timing table as the reports showed it, for a person to read: the stages indented by level with their seconds, share of the wall clock, JIT and GC and a notes column (short, on the same line, no brackets), then the process's GC and the fit and plot timings;
  • --- machine ---, last: the system, the processor and its clock, the cores and Julia threads, the memory, and the load and the free memory when the run started.

The first line of the file, datetime, stamps the last write (day, 24-hour time, offset from UTC). The cells of a row are padded with spaces to a multiple of 8 and followed by one tab, so they line up at any tab width.

results writes the log when it is given runLog = true (off by default; the fitting tests set it); call writeLog yourself otherwise, or again after results to include what came between. A folder's logs are tracked in git, which is why it is small.

Arguments

  • result: a runModel return value.
  • refChi2: the reference χ², the depositor's with its method ("CRYSOL 1.37"), printed in the run's section as the refChi2 row.
  • path, name: the log file and the section's title instead of the ones the workbook gives.

Returns

  • The path of the log, nothing without a log of the run's stages (or a workbook or a path).

Exceptions

  • SystemError if the file cannot be written.

BAYSOL.Pipeline._modesSheet — Method

The modes sheet, one row for each posterior mode the chains settled in (nothing when there is only one): its share of the posterior mass by bridge sampling, the logMass and its logMassErr (nats), the number of chains in it and kept (0 for a mode whose share is below Inference.MODE_NEGLIGIBLE, which keeps no draws).

source
BAYSOL.Pipeline._optimaSheet — Method

The optima sheet, one row for each optimum that carries posterior mass (nothing unless there is more than one or chains were added at one): its share of the Laplace mass, the number of chains that ended there and how many of them started there.

source
BAYSOL.Pipeline._resultSheets — Method

The map, quantiles_<interval> and stdevFromPrior sheets ([] when every draw diverged and there is no MAP):

  • map: parameter | value, the MAP value of every reported quantity;
  • quantiles_<interval>: parameter | quantileLo | quantileHi | boundLo | boundHi, the empirical quantile pair of each quantity and the extreme draws inside it;
  • stdevFromPrior: parameter | zMap | zQuantileLo | zQuantileHi, for the four parameters with a prior, how many prior standard deviations (θ-space) the MAP value and the quantile pair lie from the prior mean.
source
BAYSOL.Pipeline._runRows — Method

The (names, values) of the rows of the run (see _runSheet), in the order they are found.

source
BAYSOL.Pipeline._runSheet — Method

The run sheet: one row for each setting and statistic of the run, with the columns section | name | value | unit | meaning. The section is model, data, sampler, convergence or output, the rows are grouped by it, value is always a number (a flag is 0 or 1; exclVolSat is 0, +1 when c1 sat on its upper bound and -1 on its lower one), unit is empty for a pure number, and meaning says in words what the row is and, for a check, what a worrying value is. mapParams is nothing when every draw diverged (the rows that depend on the MAP are then left out). A row whose source the run did not record is left out. The rows are those of _RUN_INFO. The data and structure choices (qMin, qMax, sigmaScale, the points left out, structureModel, addHydrogens, lmaxPinned) are rows only when they differ from the defaults.

source
BAYSOL.Pipeline._shown — Method

A path as the user would type it: relative to the working directory when that is shorter.

source
BAYSOL.Pipeline._signed — Method

x to four significant figures with a true minus sign.

BAYSOL.Pipeline._summaryLines — Method

The lines of the terminal summary of a runModel result (see printSummary): the verdict (reduced χ², the four sampled parameters with their quantile pair, one per row), the checks in words with a note for each that failed, where the results and figures went (what results recorded in the run's timing log), and the wall clock as the last line.

source
BAYSOL.Pipeline._summarySheets — Method

The summary sheets of a run, in workbook order: run, map, quantiles_<interval>, stdevFromPrior, then modes and optima when the run has them and formFactorLog (one line of text to a row) when there is a log. The quantiles sheet is named after the interval runModel logged (2sigma, else the default's); nAtoms, if given, overrides the logged atom count.

source
BAYSOL.Pipeline.printSummary — Method

Prints the summary of a runModel result to io (stdout by default), the last thing a run says:

Fit finished: reduced χ² = 0.87 on the measured points
  ρₑ   0.3362  (0.3361–0.3362)
  δρ₁  −1.06  (−1.15 – −1.03)
  δρ₂  …
  δρ₃  …
  Checks:  converged (R̂ 1.002)
           no divergent transitions
           8 of 8 chains used
  Results: out/res.xlsx
  Figures: out/plots/
  Log:     out/out.LOG
Wall clock: 141.3 s

The χ² is the reduced χ² of the MAP on the measured points. Each of ρₑ, δρ₁, δρ₂ and δρ₃ is shown as its MAP value with the quantile pair of the run (the sigma of runModel) in brackets. Every line is short (a parameter, a check or a file per row) so it fits an 80-column terminal. A check that fails adds a Note: line in words (chains not converged, over 1 % divergent transitions, c1 on its bound, several posterior modes). The paths are the ones results wrote, so call this last; the line for a file that was not written is left out.

Returns

  • nothing.
source
BAYSOL.Pipeline._MAX_COLUMN_WIDTH — Constant

The widest a column is made (characters); a column with longer text wraps it.

source
BAYSOL.Pipeline._cell — Function

A cell of the workbook: a finite number rounded to sigfigs significant figures (TABLE_SIGFIGS by default; nothing is rounded at 17 or more, which a Float64 cannot carry); a number that is not finite (a statistic that could not be computed, NaN) is an empty cell, since a spreadsheet has no NaN and would hold it as text. Anything else is as it is, but an integer a Float64 cannot hold exactly (2^53 or more: a seed a user gave) is text.

source
BAYSOL.Pipeline._drawsSheet — Method

The draws sheet: one tidy table, a row for each posterior draw of fit, in the order the chains are stored, with a frozen header row. The columns, with units in the header text: chain and draw (1-based, within the chain); the sampled parameters rhoE (e⁻/Å³) and deltaRho1..3 (units of UNIT_OF_δρ e⁻/Å³); the quantities derived from each draw that the result already holds, scale, bkgrndCorr, exclVolCorr (the profiled c1) and chi2FitGrid (the reduced χ² on the fitted grid); and the sampler's flags of the draw: logDensity, divergent (1 for a divergent transition), treeDepth, nSteps, stepSize and acceptanceRate. A flag the sampler's statistics do not carry has no column. Nothing is recomputed: every column is read off fit.

source
BAYSOL.Pipeline._fillSheet! — Function

Writes the table sh (made by _sheet) into the workbook sheet sheet, the header row first; a column shorter than the longest is padded with empty cells.

source
BAYSOL.Pipeline._fitColumns! — Method

Sets the width of each column of sheet to fit its header and its longest cell (up to _MAX_COLUMN_WIDTH; a column with longer text wraps it, aligned to the top of its row) and makes the header row bold. cols are the cells of each column, in the header's order.

source
BAYSOL.Pipeline._sheet — Method

A table of the numbers behind the figures: name (a sheet of the workbook), the column names header and the columns cols (vectors of numbers, strings or missing; a shorter one is padded with empty cells). With frozen = true the header row stays in view when the sheet is scrolled.

source
BAYSOL.Pipeline._sheetNames — Method

names as sheet names of a workbook: at most 31 characters (Excel's limit), none repeated (a repeat gets _2, _3, …, within the limit).

source
BAYSOL.Pipeline._writeTables — Method

Writes the sheets of a run to dir/<name>.xlsx. The workbook path is recorded in log.info so that printSummary can name it.

Returns the path written.

source
BAYSOL.Pipeline._writeXlsx — Method

The sheets of the workbook written to path, in order: the first becomes the workbook's first sheet. The file is written next to its final name and then renamed, so a crash cannot leave half a workbook.

Returns
