MolecularStructure

The structure-loading pipeline (src/molecular-structure/): the atomic/ionic radius lookup, resolving a structure source (local path, PDB ID, URL), and the Molecule data model. Hydrogen placement is in Hydrogenator.

BAYSOL.MolecularStructure — Module

Molecular and atomistic model for BAYSOL.

source
BAYSOL.MolecularStructure.AMBER_NUCLEIC_NAMES — Constant

Nucleic-acid residue names that are not (or not only) wwPDB component ids but occur in pdb2pqr/Amber output and in older files, with their class and plain parent base: RNA RA RC RG RU and DNA DA DC DG DT, each also with the terminal suffixes 5, 3 and N (RA5, RG3, DAN, ...). component reports them as nucleotides (:rna/:dna, "rna linking"/"dna linking", parent the plain base: A C G U or DA DC DG DT, and the formula and hydrogen count of that base) before consulting the table, because the table also uses several of them (DA5, RG3, ...) for unrelated ligands. The one exception is RU, which the table has as ruthenium: it is left to the table, and a residue named so is taken as uracil only by the backbone-atom test of Hydrogenator.hydrogenationChoice. The CHARMM/old free-base ids ADE CYT GUA THY URA are not here: the wwPDB uses them for the free bases (non-polymers).

source
BAYSOL.MolecularStructure.BACKBONE_ATOMS — Constant

The sugar-phosphate backbone atoms of a nucleotide residue (primes spelled '; the old * is read as '), the evidence for a nucleic acid whose residue names are unknown or legacy: a residue with at least BACKBONE_MIN of them is a nucleotide.

BAYSOL.MolecularStructure.DUMMY_ZERO_FRACTION — Constant

source
BAYSOL.MolecularStructure.DUMMY_ZERO_MAX_FRACTION — Constant

Above this fraction the zero-B, zero-occupancy rule does not fire: a file whose atoms all have occupancy 0 and B 0 (SASDR99) carries no information about which atoms are dummies.

source
BAYSOL.MolecularStructure.KEEP_LIGANDS — Constant

Whether the model keeps the ligands of a structure (owner, 2026-11-11 and 2026-11-13: "nothing should be dropped"): every HETATM group that is not a water (WATER_NAMES): heme, metals, glycans, nucleotide triphosphates and other cofactors, detergent heads, placeholders (UNK, UNL, DUM) and residues the component dictionary does not know, scatters as heavy atoms, as in CRYSOL, which keeps every non-water record (ligandSelector). An atom is kept when its element (the element column, else the atom name) is one the radius table knows; a residue without component data is kept and warned about once, and an atom of an unknown element is dropped and warned about once, with the residue name and the count. Ligands carry no hydrogens except those the file gives (pdb2pqr leaves them as they are): a deficit of a fraction of a percent of the electrons; they take part in the excluded volume and the accessible surface like any atom. Waters stay out: the hydration shell stands for them. The default of the ligands keyword of loadMolecule; not a setting.

source
BAYSOL.MolecularStructure.LEGACY_NUCLEOTIDE_NAMES — Constant

Legacy residue ids (CHARMM and older files) of the nucleotide bases, with the base they stand for: ADE A, GUA G, CYT C, URI U, THY T. The wwPDB uses these ids for the free bases (non-polymer ligands), so component keeps them :other; a residue under one of these names is a nucleotide only when it carries the sugar-phosphate backbone (legacy_nucleotides): it has a P atom, or at least BACKBONE_MIN of the BACKBONE_ATOMS and its chain has at least two such residues. DAD DCY DGU DTH are not here: the table has them as D-amino acids and a sugar.

BAYSOL.MolecularStructure.NUCLEOBASE_ATOMS — Constant

The ring atoms of the nucleobases: a nucleotide residue with fewer than BACKBONE_MIN backbone atoms and none of these is a fragment (a phosphate split off as a residue).

BAYSOL.MolecularStructure.STANDARD_NUCLEOTIDES — Constant

BAYSOL.MolecularStructure.ComponentError — Type

Raised when a residue cannot be looked up: it is not in the bundled table, not in the cache and the download failed (typically offline), or its cached file is not a component file. (A name the dictionary answers "no such component" for is not an error: it is taken as an unknown, non-nucleotide residue.)

source
BAYSOL.MolecularStructure.ComponentInfo — Type

The record of a component: id (upper case), class (:dna, :rna or :other), type (the dictionary's _chem_comp.type, lower case), parent (the standard residue a modified one derives from, see below), formula (as in the dictionary, e.g. "C9 H13 N2 O9 P"), n_hydrogens (hydrogens, deuterium included, of the free component's formula), source (:builtin, :cache or :download: where this lookup found it), base (the natural base A C G U T a DNA/RNA component stands for, nothing when none or not known) and base_source (where base comes from: :parent, :self for a standard residue, :letter the dictionary's one-letter code, :ring the ring chemistry, :name the component's name; :none when base is nothing).

parent is what the dictionary declares, base the base the component stands for, declared or inferred, base_source says which. The inference is offline, in bysl extract components (dev/src/extract.jl), validated there against the declared parents, and only the bundled table has it: a component read from a cached or downloaded file has the base of its declared parent, else nothing. Nothing in loading, the force-field choice or the classification depends on parent or base.

parent === nothing means "no declared (or resolvable) parent" and is never an error: the dictionary's list is split and deduplicated (DT, DT is DT), a non-standard parent (TTD) is followed up to a standard id, and what cannot be resolved is nothing. Of the 843 DNA/RNA components of the bundled table 565 declare a parent and 278 do not (14 of those are the standard ids, the rest terminal variants and unnatural nucleotides). Nothing in loading, the force-field choice or the classification depends on the parent.

BAYSOL.MolecularStructure.Ion — Type

BAYSOL.MolecularStructure.LocalPathSource — Type

A structure already on local disk, at path. A .pdb path is used in place (no storage, no copy — it's already local); a .cif/.mmcif path is converted to a canonical .pdb stored in _storeDir, named after the file's own basename stem (e.g. fixture.cif → "fixture"). Conversion always re-runs (it's cheap and local — there's no "skip the work" benefit to be had here, only deduplication of the resulting file); if a file already exists under that name, the freshly-converted result is byte -compared against it: identical content reuses the existing file, but different content under the same name is a collision and raises StructureSourceError rather than silently overwriting or renaming around it — remove the stale file or use a different filename.

BAYSOL.MolecularStructure.Molecule — Type

Fields

  • _name::String: structure identifier (e.g. PDB ID or file stem).
  • _elms::Vector{String}: per-atom element symbol, length n.
  • _n::Int: atom count; set at construction, never recomputed.
  • _cart::Matrix{Float64}, (3, n): centred Cartesian coordinates (x, y, z).
  • _sph::Matrix{Float64}, (3, n): spherical coordinates (r, theta, phi), sharing _cart's column index.
  • _radii::Lazy{Vector{Float64}}: per-atom isolated van der Waals radius (AtomicRadii), length n.
  • _vols::Lazy{Vector{Float64}}: per-atom geometrically-computed excluded volume from excludedVolume, length n.
  • _rMax::Lazy{Float64}: largest per-atom radius in _radii.
  • _tree::Lazy{KDTree}: KDTree over _cart, shared across neighbour queries.

BAYSOL.MolecularStructure._inferElement — Method

Fallback element guess from an atom name, for legacy-format PDB files whose element column (columns 77-78) is blank – some pre-remediation-era files predate that column. Digits/whitespace are stripped first (e.g. "1HB2" -> "HB"). For an ATOM record (standard protein/nucleic-acid naming), only the first letter is trusted: "CA" is always the alpha carbon (Carbon), never calcium, under that naming convention. BAYSOL.MolecularStructure._legacyNucleotides — Method

The legacy-named nucleotide residues (LEGACY_NUCLEOTIDE_NAMES) among records, an iterable of (chain, number, residue name, atom name) text tuples (chain and number, with the insertion code, stripped; atom names with * read as ').

BAYSOL.MolecularStructure._pdbModel — Method
_pdbModel(path, k) -> String

The k-th model (counted from 1, in file order) of the .pdb at path, as a .pdb of its own in _storeDir: the lines before the first MODEL record, the lines of that model without its MODEL/ENDMDL records, and END. The name is <stem>_model<k>_<hash>.pdb, the hash that of the content (8 hexadecimal digits of SHA-256), so a file of the same name in another folder, or an edited file, never reuses another's copy and the caches of the hydrogens (keyed by this path) stay right. An existing copy is reused.

Exceptions

  • StructureSourceError: the file has no MODEL records or fewer than k models.

BAYSOL.MolecularStructure._resolveCanonicalPdb — Method

Shared "produce candidate .pdb, then compare-or-write-or-throw" step used by LocalPathSource and URLSource (not PDBIDSource, which has its own simpler fetch-if-missing path). Takes model 1 of the already-parsed BioStructures structure struc, writes it (filtered through _canonicalSelector: standard and nucleotide heavy atoms and the other non-water HETATM groups, no waters or hydrogens) to a temp file, then:

  • if nothing is stored under key yet, moves the temp file into place;
  • if something is and it's byte-identical, discards the temp file and returns the existing path unchanged;
  • if something is and it differs, discards the temp file and throws StructureSourceError.

model picks the model: the model-th that BioStructures lists (1, the default, is the first whatever its number); one beyond the last is a StructureSourceError that says how many there are.

Wraps any BioStructures.writepdb failure (most notably: a multi-character chain ID, which legacy .pdb cannot represent) in a StructureSourceError.

Arguments

  • struc: a parsed BioStructures structure (from read or retrievepdb).
  • key: stored filename stem, e.g. a local file's basename stem or a URLSource's id (with the model suffix of _modelSuffix for a later model).
  • model: which model to write, counted from 1.
source
BAYSOL.MolecularStructure._resolveParent — Function

The standard parent of a component from the dictionary's raw parent text: comma/blank separated lists are split and deduplicated ("DT, DT" is DT); a single standard id (STANDARD_NUCLEOTIDES) is kept; a single non-standard id (TTD) is followed through the table up to a standard id, with a guard against cycles. nothing when there is no declared parent, the list names several different ones, or the chain does not end in a standard id (standard, the nucleotides' by default). Never an error. parentOf(id) gives the raw parent text of another component (nothing if none or unknown).

BAYSOL.MolecularStructure.dummyLikeResidues — Method
dummyLikeResidues(path) -> NamedTuple

Find what looks like a dummy-atom or fragment model (CORAL/EOM linker residues, UNK dummy residues, bead models, phosphates split off as separate residues), for which BAYSOL's behaviour is undefined. Detection only: nothing is changed. A text scan, chains as sanitizedCopy would relabel them. The rules, per residue:

  1. its name is one of DUMMY_RESIDUE_NAMES and it is an ATOM record (a HETATM UNK is an unknown ligand, as in SASDTK5, not a dummy residue);
  2. an ATOM-record residue with at most DUMMY_MAX_HEAVY_ATOMS heavy atoms, unless the residue is a water, an ion or a component that small itself (a formula of at most that many heavy atoms) or its name cannot be a component id (K+);
  3. a protein residue (the dictionary type names a peptide) lacking one of PROTEIN_BACKBONE_ATOMS;
  4. a nucleotide residue with fewer than BACKBONE_MIN of the BACKBONE_ATOMS and none of the NUCLEOBASE_ATOMS;

and for the structure: duplicate atoms (same chain, residue, atom name, alternate location), and more than DUMMY_ZERO_FRACTION of the atoms with a B-factor of exactly 0.00 and an occupancy of 0.

Returns

(; residues, duplicates, zeroFraction, n): residues, a vector of (; chain, num, name, reasons) for the flagged residues (reasons, symbols :name :few_atoms :protein_backbone :nucleotide_fragment); duplicates, the number of duplicate atoms; zeroFraction, the fraction of atoms with B = 0 and occupancy 0; n, the number of findings (flagged residues, plus one for each structure-level rule that fires).

Exceptions

  • ComponentError: a residue name that could not be looked up (offline) and is needed.
  • SystemError: path cannot be read.

BAYSOL.MolecularStructure.sanitizedCopy — Method
sanitizedCopy(inPath, outPath; waters = false) -> Union{Nothing,NamedTuple}

Make the .pdb at inPath readable when it needs it, writing the repaired copy to outPath: a TER-separated block that reuses a chain id and its residue numbers (two molecules both labelled A) is given the next unused chain id (CHAIN_LETTERS), and later copies of true duplicate atoms (same chain after relabelling, residue number, atom name and alternate-location id), which BioStructures refuses and which would count twice in the scattering profile, are dropped. Both are logged (@warn, once per structure). Chain ids never reach the scattering model, so the relabelling changes nothing in the profile; the two real chains stay in the model.

With waters = true every record of a water residue (WATER_NAMES: ATOM, HETATM and the ANISOU after them) is dropped as well, whatever the name of its oxygen (O, OW, O1): waters never scatter in BAYSOL and pdb2pqr's water optimisation fails on a water oxygen it does not know. That is what the hydrogenation step asks for. The count is logged at debug level only (waters are very common) and not part of the result.

Returns

nothing when the file needs none of this (nothing is written), else (; relabelled, dropped), the numbers of chains relabelled and duplicate atoms dropped.

Exceptions

  • MoleculeError: more chains need new ids than there are ids.
  • SystemError: a path cannot be read or written.
